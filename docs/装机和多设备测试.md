# 装到多台设备，然后测

这份东西只干一件事：让你在**任意一台电脑**上，用**一条命令**装好，再用**一条命令**确认它真能用。

不需要懂 MCP、不需要懂 npx、不需要手改任何配置文件。

---

## 一、每台设备都做这两步

### 第 1 步：装

打开终端（Windows 按 `Win` 键，搜 `PowerShell`，回车），把下面这行**整行复制**进去，回车：

```
npx -y agentdeck-super@latest --all
```

第一次要下载，等 1–3 分钟。看到「**装好了。下一步：**」就是成功。

> **如果你在用 Claude Code**，也可以用它的插件安装（更短）：
> ```
> /plugin install nexi --marketplace wm17717783258-boop/agentdeck-super
> ```
> 或者在 Claude Code 里敲 `/plugin`，在插件面板里搜 `nexi`，点安装。
>
> **已经装过、想升级的注意**（2026-11-10 实测踩到）：再敲 `install` 是**空操作**，
> 它只会提示一句「已经装过了」，版本号一动不动。升级必须用：
> ```
> /plugin marketplace update nexi
> /plugin update nexi@nexi
> ```
> 命令行等价：`claude plugin marketplace update nexi` → `claude plugin update nexi@nexi`。
> 升完要**重启 Claude Code**，旧进程里跑的还是旧的那份。

### 第 2 步：确认这台机器到底行不行

```
npx -y agentdeck-super doctor
```

它会用人话告诉你三件事：

```
Nexi 自检 · v1.11.15

① 运行环境
  ✅ Node 22.22.2
  ✅ 22 个工具 都能列出来

② 接进宿主了吗
  ✅ Claude Code  已注册
  ✅ Codex  已注册
  ·  Cursor  没装，跳过

③ 真能干活吗（在临时目录里试，不碰你的数据）
  ✅ 货架  7 套皮肤（付费 4 套）
  ✅ 开单  ord_955a6544a34b（极光）
  ✅ 皮肤图  35/35 帧画得出来

────────────────────────────
结论：这台机器可以直接用。
```

**看最后一行就够：**

| 你看到 | 意思 | 怎么办 |
| --- | --- | --- |
| `结论：这台机器可以直接用。` | 好了，去用 | 没了 |
| `结论：还不能用 —— 宿主没接上 nexi` | 装了插件但没接进宿主 | 再跑一次第 1 步，加 `--force` |
| `结论：还不能用 —— Node 版本太低` | Node 太老 | 去 nodejs.org 装 22 或更高 |
| `结论：还不能用 —— 没有可用宿主` | 这台机器没有任何支持的 Agent | 先装 Claude Code / Codex / Gemini CLI 里的任一个 |

### 出问题了怎么办

`doctor` 最后会打印一个方框：

```
┌────────────────────────────────
│ 机器 win32/x64 · node 22.22.2
│ 版本 1.11.15
│ 宿主 claude-code=ok codex=ok cursor=没装
│ 功能 货架=ok 开单=ok 皮肤图=ok
│ 结论 PASS
└────────────────────────────────
```

**把这个方框整段复制发我**，不用描述、不用截图、不用解释。我看一眼就知道哪坏了。

## 二、多台设备：怎么确认它们真的是"两台"

`doctor` 只证明"这台能用"。要证明**两台之间真能通**，走完下面三步。

前提：两台都装好（第 1 步），都在同一个 WiFi / 同一个路由器下。

### 第 1 步：第一台（A）开房

```
npx -y agentdeck-super@latest pair host
```

它会起一个中继，然后打印这样一段：

```
中继地址：http://192.168.1.10:8899
席位：8（房主 1 席，可加入 7 台客人设备）

===== 把下面这一行发到第二台设备（原样粘贴，别改） =====
npx -y agentdeck-super@latest pair guest --invite "http://192.168.1.10:8899/?room=…&t=…"

那台设备不用装本项目源码，也不要授权码，有 Node 就能跑。
…
===== 复制结束 =====
```

**这个窗口别关** —— 中继跑在这个进程里，关了房间就没了。

> 注意那个地址是 `192.168.x.x` 这样的局域网地址，不是 `127.0.0.1`。
> 它要是报「找不到可用的局域网地址」，说明这台机器没连网 —— 接上 WiFi 再跑一次。

### 第 2 步：第二台（B）进房

把上面**那一整行**复制到 B 上，回车。成功会看到：

```
成员 2 人：真机配对(owner)、乙机-测试
进房并同步成功，已占用 1 席（乙机-测试）。
```

两边都 `npx -y agentdeck-super@latest pair check`，都能看到「成员 2 人」和「可达性：连得上」，就是通了。

### 第 3 步：证明任务真的跨机了（唯一算数的证据）

前两步只证明"能握手"。要证明"能一起干活"，看任务能不能真的从 A 流到 B、再流回来。

在 A 上**另开一个窗口**（原来的窗口要一直开着）：

```
npx -y agentdeck-super@latest pair task add --title "跨机验收任务" --acceptance "乙机看到并领取"
npx -y agentdeck-super@latest pair sync
```

在 B 上：

```
npx -y agentdeck-super@latest pair sync
npx -y agentdeck-super@latest pair task list
```

B 能看到同一条任务（编号一致）：

```
· task_f994ba187a [pending] 跨机验收任务  角色:worker
    验收：乙机看到并领取
```

在 B 上领取并做完：

```
npx -y agentdeck-super@latest pair task claim --id task_f994ba187a
npx -y agentdeck-super@latest pair task done --id task_f994ba187a --output "乙机已完成"
npx -y agentdeck-super@latest pair sync
```

回到 A 再 `sync` 一次，看到：

```
✓ task_f994ba187a [done] 跨机验收任务
```

**走到这里，两台设备才算真的通了。** 这一步是实跑过的，不是设计文档。

> 同一台机器上开两个窗口"模拟两台"，不能代替这一步：本机 127.0.0.1
> 永远通，会把这个环节的问题全盖住。跨机看的是局域网地址能不能通。

### 第 4 步：让两个 Agent 也进这间屋（1.11.14 起自动）

命令行通了不等于**你的 Agent** 通了。以前就是这里断的：`pair` 打印"进房成功"，
你切回自己的项目问 Agent「房间里有谁」，它答「还没有配置 relay 地址」。

现在配对会直接把房间和小组写到**这台设备**的公共位置，所以换个目录也认：

```
在你的 Agent 里说：房间里有谁？
```

应该看到（不用改任何配置、不用重开终端）：

```
【deck_room】房间信息：f56a8af5-… (真机配对房间) · 成员 · 席位 …
成员 2 人：真机配对(owner)、乙机
```

再说一句「team_board 有哪些小组」，能看到 A 建的那个 `team_…`。

**真让两个 Agent 干一件活**（这才是协作，不是握手）：

| 在哪台 | 说什么 | 应该看到 |
| --- | --- | --- |
| A | `在 team_board 里加个任务：跨机验收任务` | `已添加任务 task_…` |
| A | `deck_room 同步一下` | `推上去 1 条` |
| B | `deck_room 同步一下` | `拉回来 … 落到本机任务板 1 条` |
| B | `team_board 列一下任务` | 看到同一条 `task_…` |
| B | `把这条任务领了，然后标记完成` | `已领取` → `已标记完成` |
| B | `deck_room 同步一下` | `推上去 1 条` |
| A | `deck_room 同步一下` → `team_board 列一下` | `✓ task_… [done]` |

装好之后，在你用的那个 Agent（Claude Code / Codex / DSH…）里直接说人话就行：

| 你说 | 应该发生什么 |

## 三·五、它不分系统 —— 一个包，三张表

先把这件事说死：**Nexi 只有一个产物**。同一份 `agentdeck-super` 包，
Windows / macOS / Linux 装的是同一个 tarball，代码一行不改，没有"Windows 版 / Mac 版"。

唯一跟系统有关的，是**宿主自己把配置放在哪** —— 那是 Claude / Codex / VS Code 的规矩，不是我们的分支。
想知道你机器上会写哪，跑这一条，它把三个系统一次列出来（`←` 是当前这台）：

```
npx -y agentdeck-super@latest where
```

```
一个包，三个系统：agentdeck-super 用同一份代码跑，hosts 表只差「宿主把配置放哪」。
本机：win32（下面标 ← 的那列就是本机实际会写的路径）

Claude Desktop（claude-desktop）
  ← win32  C:\Users\你\AppData\Roaming\Claude\claude_desktop_config.json
    darwin ~/Library/Application Support/Claude/claude_desktop_config.json
    linux  ~/.config/Claude/claude_desktop_config.json
```

机器可读版本：`nexi where --json`（每行带 `win32 / darwin / linux` 三个字段，可直接进脚本比对）。

> **这版修掉的真缺陷**：以前 Claude Desktop / VS Code / Cline / Zed 这四个宿主只写了 Windows 路径，
> 在 macOS 上会算成 `~/AppData/Roaming/...` —— 路径不存在，探测就说"宿主未安装"，
> 用户看到的现象是"插件不支持 Mac"。现在按系统查表，并且有 **12 条矩阵测试**在这台
> Windows 上把 darwin / linux 的路径逐字算出来核对（`tests/platform-matrix.test.mjs`），
> 谁改回 Windows 专用写法，测试立刻红。
>
> **仍然没做到的**：手上没有第二台 Mac / Linux 真机，所以"在真 Mac 上点开 Claude Desktop
> 看到 23 个工具"这一步没有实测过；矩阵测试锁的是**路径算得对**，锁不住宿主 GUI 的行为。
> 这一条不改口。

### 它现在能接哪些 Agent

内置 **25 家**（Claude Desktop / Claude Code / Codex / Cursor / Windsurf / Cline / Continue / Gemini CLI / Qwen / Copilot CLI / Zed / VS Code / OpenCode / Roo Code / Kilo Code / Kilo CLI / Kiro / LM Studio / Factory / Junie / Qoder / Antigravity / Amazon Q / Amp / Crush）。

## 四、这台机器上现在到底装了什么

装完之后，文件在这些地方（不用记，`doctor` 会告诉你）：

| 平台 | 位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Nexi` |
| macOS | `~/Library/Application Support/Nexi` |
| Linux | `~/.local/share/nexi` |

里面是插件本体 + 一个固定启动器。**以后升级只切版本指针，宿主配置里的路径不变**，所以升级不会把你的配置搞乱。

另外有一份**跟机器走**的状态（房间会话、小组、任务板），三平台都在：

| 平台 | 位置 |
| --- | --- |
| 全部 | `%DSH_HOME%`（没设就是 `~/.dsh`）下的 `agentdeck-super` |

> 为什么不放项目目录：房间/席位是"这台设备在这间屋里"，跟人走不跟项目走。
> 放项目目录就会出现"在 A 目录配对成功、到 B 目录 Agent 说没配对"。

## 五、常见问题

**Q：`pair` 说进房成功，Agent 却说"没配 relay 地址"？**
1.11.14 起不会了 —— 配对直接把房间写进上面那个"跟机器走"的位置。
若你还在旧版（`doctor` 里版本号 ≤ 1.11.13），升级即可：`npx -y agentdeck-super@latest --all`。

**Q：A 上建了任务，B 的 Agent 看不到？**
两边都要 `deck_room 同步一下`。推送是手动的（不偷偷联网）。另外确认两边看的是同一个小组 id（`team_board 有哪些小组`）。

**Q：`npx` 是什么？要装吗？**
不用。装了 Node 就自带 `npx`。Node 从 [nodejs.org](https://nodejs.org) 下 LTS 版即可（要 22 或更高）。

**Q：我在国内，npx 下载很慢 / 卡住。**
换国内镜像再跑：
```
npx --registry=https://registry.npmmirror.com -y agentdeck-super@latest --all
```

**Q：装完 `nexi` 提示「不是内部或外部命令」。**
正常 —— 用 npx 装不会进 PATH。把命令写成 `npx -y agentdeck-super doctor` 就行，或者用完整路径：
```
node "%LOCALAPPDATA%\Nexi\bin\nexi.mjs" doctor
```

**Q：我不想装了，怎么卸？**
```
npx -y agentdeck-super uninstall --all
```
只卸宿主配置，不动你的数据。要连文件一起删，再删掉上面表格里那个目录。

**Q：`doctor` 会不会动我的数据？**
不会。它开单、画皮肤全在系统临时目录里做完就删。你要验证这点，跑完看一眼当前目录有没有多出 `market/` 文件夹 —— 不会有。（这条有测试守着：`tests/cli-doctor.test.mjs`）
