**1.11.5 的安装与分发补充边界：**

- `nexi-pair guest --name "姓名-部门"` 已经能让房主在 `members` 里区分设备/人；

- 支持 MCP 的宿主可以直接接；不支持 MCP 的 Agent 需要适配器，不能宣传成“所有 Agent 自动支持”。

## 五、我在真机上抓到的坑（写在这是为了你别踩）

这些不是理论问题，是真跑之后暴露的：

| 坑 | 现象 | 现在怎么处理 |
| --- | --- | --- |
| 系统 `tar` 不支持中文路径 | 解包报 `Failed to open archive` | 改用自带 `lib/untar.js`，不依赖外部 tar |
| 配对选了虚拟网卡 | 选了 `198.18.0.1`（VPN 类），对面连不上 | 地址判定排除 VMware/WSL/Docker/Hyper-V/Meta/TUN 等 |
| 邀请链接里的 `&` 被 shell 吃掉 | 报"邀请已失效"，看着像插件坏了 | 支持 `--invite-file` 和 `NEXI_INVITE` 环境变量 |
| 进房后 sync 说"没配 relay" | 第二次调用丢了上次的地址 | 进房成功就把地址记进 `last.json`，后续自动沿用 |
| `dsh://` 深链里没有地址 | 对面无从连 | 配对优先给带 `http://` 地址的网页形态 |
| 验收脚本依赖用户家目录私钥 | 换台机器直接失败 | 改成现场生成临时密钥，不碰用户真实材料 |
