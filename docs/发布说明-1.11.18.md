# 1.11.18 —— 把自检里剩下的缺口补上

**一句话**：上一版把"能接哪些 Agent"做成了通道，但自检里点出四件运维件还缺：YAML 宿主、把自己卸干净、运行日志、更新检查。这版全做了，而且都带会红的测试。

## 一、YAML 写入器（Goose / Continue 新版）

以前这两家只能 `nexi snippet` 手粘 —— 我们生成了片段，用户还得自己找文件、找缩进、找位置。现在直接写。

| 宿主 | 文件 | 结构 | 字段 |
| --- | --- | --- | --- |
| **Goose** | macOS/Linux `~/.config/goose/config.yaml`；Windows `%APPDATA%\Block\goose\config\config.yaml` | `extensions.<id>`（map 成员） | `type: stdio` / `name` / `cmd` / `args` / `envs` / `enabled` / `timeout` |
| **Continue** | `~/.continue/config.yaml`（新版）；老的 `config.json` 仍然认 | `mcpServers:`（**列表**，每项带 `name`） | `name` / `type: stdio` / `command` / `args` / `env` |

注意两家的差异不是"换个 key"这么简单：Goose 是 map 成员、Continue 是列表项；Goose 用 `cmd` + `envs`，Continue 用 `command` + `env`。写错一个字段，宿主不会报错，只会**静默不加载**。

### 为什么没引 yaml 包

1. 这个包的硬要求是零运行时依赖、离线能起 —— 为两个宿主多拖一棵依赖树，等于让所有用户多下一个包。
2. 更要紧的是**别毁用户的文件**：整份重新序列化会把注释、空行、键顺序、引号风格全冲掉，diff 出来一片红。宿主配置是用户自己也在编辑的东西。

所以 `lib/connect/yaml.js` 做的是**按行切片**：找到顶层 key 的块范围 → 在块尾插一段带哨兵注释的子项 → 卸载时按哨兵整块剪掉。不解析整份文档，就不动别人的部分。

明确拒绝而不是瞎猜的两种情况：

- `extensions: { ... }` 这种非空行内 map → 报冲突，让用户手改或 `--force`；
- 已有同名 `nexi:` 但**不是我们写的** → 默认拒写，`--force` 才覆盖。

顺带把 `kind: 'auto'` 做出来了：Continue 两代格式并存，装到 `.yaml` 就按 YAML 写、装到 `.json` 就按 JSON 写，不靠猜。

## 二、`nexi uninstall --self`：真的卸干净

以前"卸载"只摘宿主里的条目，安装目录和状态目录得用户自己去删。现在一条命令：

```
nexi uninstall --self           # 只打印计划（不可逆操作，默认不动手）
nexi uninstall --self --yes     # 真删
nexi uninstall --self --yes --keep-state   # 保留授权 / 账本 / 任务板 / 注册表
```

难点是**删自己**：跑的进程正踩在安装目录里，Windows 上删运行中目录必失败。所以分三段：

1. 活着的进程摘宿主条目（它懂各家格式，也只有它能当场做）；
2. 能当场删的当场删，**删完立刻回读**确认不在了；
3. 删不掉的交给独立清理进程 —— 它等父进程退出后再删，把结果写进 `%TEMP%\nexi-self-uninstall-*.log`，路径打印出来，用户能自己去看有没有删干净。

安全边界写死在代码里（`unsafeReason()`），不靠调用方自觉：只吃绝对路径；只删名字里带 `nexi` / `agentdeck-super` 的目录；拒绝家目录、盘根、家目录的上级。**从源码目录跑 `--self` 时，只清宿主注册项，不动源码目录** —— 那不是我们装的东西。

## 三、结构化运行日志

`$DSH_HOME/agentdeck-super/logs/nexi-YYYYMMDD.log`，一行一个 JSON：

```
2026-11-10 06:15:43 INFO  doctor  version=1.11.18 node=22.22.2 tools=23 wired=6/26 pass=true
```

- 按天分文件，单文件 5 MB 上限，超了轮转 `.1`，保留 7 天；
- `nexi logs` 看最近 30 条（`--tail N` / `--json` / `--dir` / `--clear`）；
- `token` / `secret` / `sha256` 只记长度，不落盘；超长字段截断；
- 写失败一律吞掉 —— 磁盘满、只读盘上主流程照样跑；
- `NEXI_LOG=0` 关掉，`NEXI_LOG_DIR` 换目录。

排障从此是"你跑一下 `nexi logs` 把输出贴我"，不是"把终端里那一坨复制给我"。

## 四、可选更新检查（默认关）

`nexi update --check` 或 `NEXI_UPDATE_CHECK=1`。**默认一次网络都不发** —— 这是硬承诺，"不分网络"不能靠每次启动偷偷连一下 registry 来换一个提示。

打开后：超时 1.5 秒、结果缓存 24 小时、任何异常都当"没查到"，绝不阻塞主流程、绝不弹错。第一条测试就是拿一个"被调用就炸"的 `fetch` 盯着，证明默认路径根本不碰它。

## 五、这版修掉的真缺陷

1. **`--help` 会在家目录里留下东西**：给 CLI 加运行日志后，`nexi install --help` 也会写一条日志 → 于是创建了 `~/.dsh/agentdeck-super/`。`tests/cli-help.test.mjs` 当场变红（它断言 `--help` 后 home 必须是空的）。修法：`--help` 不记日志 —— 帮助是只读的，这条本来就写在代码注释里。
2. **`nexi config` 对 YAML 宿主给的是 JSON 文本**：`kind` 直接抛 `host.kind`，Continue 拿到的是 `auto` 这种没信息量的值，`--out` 还按 `.json` 起名。现在按**默认落点**解析 kind，`.yaml` 宿主写 `.yaml` 文件。
3. **`nexi host list --md` 把家目录写进文档**：生成的是公开文档，里面有 `C:\Users\<你的名字>\...`。现在缩成 `~` / `%APPDATA%`。

## 七、边界（不改口）

- **26 家里本机真装过 6 家**（Claude Desktop / Claude Code / Codex / Gemini CLI / Qwen / Copilot CLI）。Goose 与 Continue 的路径和字段名来自官方文档逐字核对，**没有在真宿主上点开验证**。这条只有真机能解决。
- 仍然没有第二台 Mac / Linux 真机。路径矩阵锁的是"算得对"，锁不住"真 Mac 上点开看见 23 个工具"。
- YAML 写入器只覆盖块状 map / 块状 seq / 流式数组这一档；锚点、别名、多文档 `---` 不处理（遇到会拒绝改写，不会猜）。
- `uninstall --self` 的"删完回读"由清理进程完成，CLI 退出后才知道结果 —— 所以它打印日志路径，而不是假装"已经删干净了"。
- npm 未发布，等你点头。
