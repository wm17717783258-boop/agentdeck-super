两处外部依赖怎么解决（1.11.2）
================================

你问的两处是：
  ① 真实商户号（门槛⑥「真钱进账」）
  ② 公网部署要 HTTPS（跨机 relay 之前只讲 HTTP）

下面分开说：**哪些我已经能自己解决、哪些必须你出手**，以及具体怎么做。

════════════════════════════════════════════════════════════════
① 真实商户号
════════════════════════════════════════════════════════════════

【我已经做完的】支付代码路径全链路验证
  命令：node tools/verify-billing-live.mjs
  证据：docs/evidence/billing-live-1.11.2.txt（26 项，全过）
  做法：起一个**严格照 Stripe 在线 API 形状应答**的本地服务器，把适配器指过去，验：
    ✅ 请求真打到 POST /v1/checkout/sessions
    ✅ 带 Bearer 鉴权头、Content-Type 是 form-urlencoded（Stripe 的硬要求）
    ✅ 表单字段名对：mode / line_items[0][price_data][unit_amount] / currency / metadata[orderId]
    ✅ 金额按**分**传（Stripe 的最小货币单位）
    ✅ 拿到了 https://checkout.stripe.com/... 收银台 URL
    ✅ Webhook 验签：真签名过、假签名拒、**改了内容就对不上**
    ✅ 退款真打到 POST /v1/refunds，带对 payment_intent
    ✅ 渠道连不上时**结构化失败**，绝不把 paid 设成 true
    ✅ 参数不齐时拒绝，且**不发出半个请求**
  结论：**代码路径已通**。换真 key 只改配置，代码一行不动。

【必须你出手的】去 Stripe 注册拿测试 key（免费，5 分钟）
  1. 打开 https://dashboard.stripe.com/register 注册（不要钱，不绑卡也能开始）
  2. 登录后切到 **Test mode**（右上角开关）
  3. 左侧 Developers → API keys
  4. 复制 **Secret key**（sk_test_… 开头）
  5. Developers → Webhooks → Add endpoint
        Endpoint URL：https://你的域名/adbp/pay/stripe/webhook
        要订阅的事件：checkout.session.completed、charge.refunded
     建完复制 **Signing secret**（whsec_… 开头）

  然后配上（两种方式任选）：
    · 环境变量：
        AGENTDECK_PAY_PROVIDER=stripe
        AGENTDECK_PAY_SECRET=sk_test_xxx
        AGENTDECK_PAY_WEBHOOK_SECRET=whsec_xxx
    · 或插件配置里 billing.provider / billing.stripe.secretKey / webhookSecret

  配完跑这个，它会**真的去 Stripe 建一个 Checkout Session**：
      node tools/verify-pay.mjs
  然后你在 /deck 上点「买 ¥18」，应该会跳到 Stripe 的收银台。
  用 Stripe 的测试卡号付款（不会扣钱）：
      卡号 4242 4242 4242 4242 · 任意未来日期 · 任意 CVC
  付完回来，订单状态应该真的变成 paid。

【最后一步：真钱】
  上面走通之后，把 Test mode 的 key 换成 **Live key**（sk_live_…），
  再走一遍真实小额（比如真的付 1 元再退掉）。
  那一步之后，「真实支付」这条门槛才算真的过。
  ——这一步只有你能做，因为它涉及你的银行账户和身份认证。

  顺带说：国内渠道同理。
    · 微信支付 / 支付宝：要**企业营业执照**才能申请商户号（个人拿不到）。
    · 没有营业执照的话，走 Stripe 最省事（个人可用，能收国际卡）。
    · 代码里 wechat.js / alipay.js 适配器已经写好了，拿到号填配置即可。

════════════════════════════════════════════════════════════════
② 公网 HTTPS
════════════════════════════════════════════════════════════════

【我已经做完的】relay 现在**原生支持 TLS**
  之前：relay 只会 HTTP，公网部署必须自己加一层反代——对自建用户是额外门槛。
  现在：直接给它证书就行。

  2026-11-08 又用 Cloudflare Quick Tunnel 真跑了一次公网入口：
    docs/evidence/public-1.11.2.txt       → healthz 200 / 无 token 401 / 握手 200 / 23 工具
    docs/evidence/public-pair-1.11.1.txt  → 历史公网 relay 配对：进房、2 人、任务 claim + done 回传
  边界：public-1.11.2 是公网 MCP 验收；配对证据只有历史 1.11.1 的同机双安装；Quick Tunnel 是临时域名，不是长期托管。
  真双物理机、跨操作系统和真实商户扣款仍需你按操作手册另跑。

  另外补了 tools/make-cert.mjs：**本机没有 openssl / mkcert 也能生成自签证书**
  （Node 自带密钥对，X.509 的 DER 我们按规范拼，不引依赖）。

【方案 A：局域网自用（最快）】
  1. 生成自签证书：
       node tools/make-cert.mjs --out ./certs --cn 192.168.1.10 --alt "192.168.1.10,localhost"
  2. 起 HTTPS relay：
       node tools/relay-server.mjs --port 8787 --host 0.0.0.0 ^
         --tls-cert ./certs/relay-cert.pem --tls-key ./certs/relay-key.pem
     → 它会打印 https://192.168.1.10:8787，别的电脑填这个
  3. 已验证：本机实测 HTTPS relay 起得来，`/healthz` 返回 200

  ⚠️ 自签证书浏览器会报"不受信任"——这是自签的必然，不是 bug。
     局域网内部用没问题。

【方案 B：公网给别人用（推荐，免费）】
  用 Let's Encrypt 申请真证书，别人访问不会有任何警告：
    1. 一台有公网 IP 的服务器（VPS，最便宜的每月几美元）
    2. 一个域名，A 记录指向这台服务器
    3. 装 certbot：
         sudo apt install certbot
         sudo certbot certonly --standalone -d relay.你的域名.com
       证书会落到 /etc/letsencrypt/live/relay.你的域名.com/
         fullchain.pem  ← 这是 --tls-cert
         privkey.pem    ← 这是 --tls-key
    4. 起 relay：
         node tools/relay-server.mjs --port 443 --host 0.0.0.0 ^
           --tls-cert /etc/letsencrypt/live/relay.你的域名.com/fullchain.pem ^
           --tls-key /etc/letsencrypt/live/relay.你的域名.com/privkey.pem
    5. certbot 会自动加续期定时任务（90 天一次）

  两台的客户端都填：
      在插件配置里 cloud.relayUrl = https://relay.你的域名.com
      或 <工作区>/.agentdeck/ 下的配置里改

【方案 C：懒得弄证书】
  用 Cloudflare（免费档）：把域名托管到 Cloudflare，开橙色云朵代理，
  回源用 HTTP，外面自动是 HTTPS。适合不想碰证书的人。

一句话总结
════════════════════════════════════════════════════════════════
  · 支付：**代码路径已经验完（26 项）**，你去 Stripe 拿个免费测试 key 就能跑到
    "真的跳出收银台、测试卡付完状态变 paid"。最后换 Live key 收真钱那一步只能你做。
  · HTTPS：**relay 原生支持 TLS 了**，还配了生成自签证书的工具。
    局域网自用一条命令；公网用 Let's Encrypt（免费）或 Cloudflare。

  这两件事剩下的部分都不是代码问题，是"要你的账号/域名/服务器"。
  代码这边已经全部就位。
