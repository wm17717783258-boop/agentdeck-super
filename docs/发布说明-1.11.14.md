# Nexi 灵犀 1.11.14 发布说明

发布日期：2026-11-10
包名：`agentdeck-super`

## 这版修的是"配对成功了，但 Agent 看不见房间"

上一版把命令行这条路打通了。真机再走一步就发现没通到底：

```
$ npx -y agentdeck-super@latest pair guest --invite "…"
成员 2 人：真机配对(owner)、乙机
进房并同步成功，已占用 1 席（乙机）。

（切回自己的项目，问 Agent）
你：房间里有谁？
Agent：【deck_room】还没有配置 relay 地址，跨机房间连不出去。
```

命令行说"在屋里"，Agent 说"没这屋"。中间断在**两套状态**：

| 谁 | 房间会话存哪 | 结果 |
| --- | --- | --- |
| `pair` | `.nexi-pair/`（配对目录） | 它自己知道 |
| Agent（宿主里的工具） | **当前项目目录** 下的 `.agentdeck/rooms` | 换个目录就不认识 |

## 改法：房间跟机器走，不跟项目走

- 房间会话（roomId / 席位 / 同步游标 / relay 地址）和小组板，统一挪到**机级目录**
  `$DSH_HOME/agentdeck-super`（没设 `DSH_HOME` 就是 `~/.dsh/…`）。
  这和授权、桌宠是同一个口径：**一台设备一个席位**。
- `pair host` / `pair guest` 直接写这个目录，所以配完在你任何项目里问 Agent 都认。
- 新增配置项 `roomRoot`（留空即机级默认），给需要自定义的场景留口子。

副作用说清楚：**以前在某个项目里进的房间，升级后不会被自动认领**（那是旧位置的数据）。
重新 `pair guest` 进一次即可；本地任务板数据不受影响。

## 这版怎么验的

两台"设备" = 两个独立机级根 + 两套独立配对状态，走真实网卡地址：

1. A `pair host` → 拿到邀请与 `team_…`
2. B `pair guest` → `成员 2 人`
3. **换到毫不相干的项目目录**，用 Agent 真实调用路径（`nexi call`）问房间：
   → `房间信息：… 成员 2 人：真机配对(owner)、乙机`（不再说没配 relay）
   → `team_board teams` 里能看到 A 建的那个 `team_…`
4. 任务真的跨机往返：A 加任务 + `sync` → B `sync` 看到同一条 → B 认领 + 完成 + `sync`
   → A `sync` 看到 `✓ done`

新增 `tests/pair-agent-visible.test.mjs` 钉住这条链，并做了两次**突变验证**：

| 故意改坏 | 测试结果 |
| --- | --- |
| 把房间会话根改回"项目目录" | 立刻红：`还没有配置 relay 地址` |
| 把小组板改回配对目录 | 立刻红：`小组列表里没有 team_…` |

退回去就会红，这条链以后不会被静默改回来。

## 边界

- 仍然是**同一台物理机的两个独立进程 + 真实网卡地址**，没有第二台物理电脑；macOS/Linux 未测。
- 跨网段（不同 WiFi / 4G）仍需 `--public-url` 或隧道，这版没动。
- 离线签名码换机后仍无法远程吊销。
