# 两台电脑实测指南（发布前必须跑通）

> **历史归档（1.10.0）**：本文是 1.10.0 发布时的流程，包名和证据版本均为历史值。
> 现行多设备流程只有一份：[`装机和多设备测试.md`](装机和多设备测试.md)。
> （`多设备席位测试-极简版.md` 已过期，命令在第二台设备上跑不起来。）

> 目标：在你的两台**物理电脑**上跑通协作，再发版。跑不通就不发。
>
> 本文只用真实存在的工具动作和参数：
>
> - `deck_room`：`create` / `join` / `sync` / `info` / `close` / `leave`
> - `join` 的参数是 `inviteUrl`
> - `deck_room` **没有** `send` / `pull`
> - 跨机协作靠任务板事件同步，不靠虚构的聊天动作

## 2. 电脑甲（房主）

### 2.1 解包并体检

```powershell
New-Item -ItemType Directory -Force -Path C:\nexi-A | Out-Null
Set-Location C:\nexi-A
tar -xzf <你拷来的>\agentdeck-super-1.10.0.tgz
Set-Location .\package
node .\bin\nexi.mjs doctor
```

### 2.2 一条命令起 relay + 测试授权 + 房间 + 配对小组

```powershell
node .\tools\nexi-pair.mjs host
```

它会：

- 选局域网地址；
- 启动 relay 并绑到 `0.0.0.0`；
- 生成一张本次配对专用的协作版测试授权；
- 创建“真机配对小组”；
- 建一个绑定该小组的房间；
- 打印可以整段复制给乙机的邀请。

**这个窗口必须一直开着。** 关掉后 relay 和房间都没了。

如果要看地址：

```powershell
node .\tools\nexi-lan.mjs
```

### 2.3 如果不用 `nexi-pair`，手工发码要先确认真实授权路径

授权是**机级**的，不是工作区级。默认路径：

```text
$DSH_HOME\agentdeck-super\.agentdeck\license\key.txt
```

当 `DSH_HOME` 未设置时，Windows 默认是：

```text
$HOME\.dsh\agentdeck-super\.agentdeck\license\key.txt
```

最推荐还是用 `/deck` 页面粘贴，或让 Agent 调用 `deck_license activate`。不要照抄旧文档的 `work\.agentdeck\license\key.txt`。

手工签发测试码时还必须让当前进程认对应的公钥；普通用户不要自己折腾密钥，直接用 `nexi-pair host` 的自动测试授权。

### 2.4 手工起 relay（可选）

```powershell
node .\tools\relay-server.mjs --port 8787 --host 0.0.0.0 --data .relay-data
```

看到 `http://<局域网IP>:8787` 后，保持窗口。

### 2.5 手工建房间（可选）

```powershell
node .\bin\nexi.mjs call deck_room '{"action":"create","name":"双机测试","relayUrl":"http://<甲的局域网IP>:8787"}'
```

输出两条邀请：

- `dsh://agentdeck/join?room=...&t=...`：装了 DSH 的宿主可直接打开
- `http://<甲IP>:8787/?room=...&t=...`：网页加入页，跨设备测试优先用这条

把网页形态的邀请发给乙机。

## 3. 电脑乙（客人）

### 3.1 解包

```powershell
New-Item -ItemType Directory -Force -Path C:\nexi-B | Out-Null
Set-Location C:\nexi-B
tar -xzf <你拷来的>\agentdeck-super-1.10.0.tgz
Set-Location .\package
```

### 3.2 进房间

邀请链接里有 `&`，最稳的是先存文件：

```powershell
@'
<甲机发来的网页邀请链接>
'@ | Set-Content -LiteralPath .\invite.txt -Encoding ascii

node .\bin\nexi.mjs call deck_room '{"action":"join","inviteUrl":"<甲机发来的网页邀请链接>","memberName":"乙机-测试"}'
```

正确参数是 `inviteUrl`，不是 `url`。客人不需要授权码。

也可以用 `nexi-pair guest`，它会自动进房并 `sync`：

```powershell
node .\tools\nexi-pair.mjs guest --invite-file .\invite.txt
```

## 4. 真正验任务回传

### 4.1 甲机新增任务并同步

```powershell
Set-Location C:\nexi-A\package
node .\tools\nexi-pair.mjs task add --title "乙机帮我看下日志" --acceptance "给出结论并回传"
node .\tools\nexi-pair.mjs sync
```

### 4.2 乙机拉取、看到、认领

```powershell
Set-Location C:\nexi-B\package
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

从输出复制任务号，替换 `<任务号>`：

```powershell
node .\tools\nexi-pair.mjs task claim --id <任务号>
node .\tools\nexi-pair.mjs sync
```

### 4.3 甲机确认 `running`

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

必须看到乙机的认领状态回传。只看到原任务还停在 `pending`，就是失败。

### 4.4 乙机完成，甲机确认 `done`

乙机：

```powershell
node .\tools\nexi-pair.mjs task done --id <任务号> --output "已完成，结论在输出里"
node .\tools\nexi-pair.mjs sync
```

甲机：

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

必须看到 `done` 和乙机写的产出。只在乙机本地成功不算通过。

## 5. 断 relay、重启、持久化

1. 甲机 `Ctrl-C` 停掉 `nexi-pair host`。
2. 甲机重新运行 `node .\tools\nexi-pair.mjs host`。
3. 乙机用新邀请重新进房。
4. 两边 `sync`，本地历史任务应还在。

通过标准：本地任务板不丢；旧的跨机同步会明确报错/关闭，不会挂死。

## 6. 串门（不需要 relay）

甲机：

```powershell
node .\bin\nexi.mjs call pet_visit '{"action":"invite","scope":"work","ttlHours":2}'
```

乙机用返回的 token 接收：

```powershell
node .\bin\nexi.mjs call pet_visit '{"action":"accept","token":"<token>"}'
```

乙机用甲机返回的 `box` 造加密便签：

```powershell
node .\bin\nexi.mjs call pet_visit '{"action":"ask","title":"帮我看下报表","box":"<box>"}'
```

把加密 JSON 发回甲机，甲机：

```powershell
node .\bin\nexi.mjs call pet_visit '{"action":"receive","note":<贴 JSON>}'
```

通过标准：`已加密：AES-256-GCM`，且解出后落成任务。

## 7. 判定标准

| 项 | 通过标准 |
| --- | --- |
| 装 | 两边都能 `node .\bin\nexi.mjs list` 列出 23 个工具 |
| 建/进房 | 乙机凭邀请进房，两边显示同一个 `roomId` |
| 任务下发 | 乙机 `task list` 能看到甲机任务 |
| 任务认领 | 乙机 `claim` 后，甲机 `sync` 能看到 `running` |
| 任务完成 | 乙机 `done` 后，甲机 `sync` 能看到 `done` 和产出 |
| 持久化 | relay 重启后本地历史任务还在 |
| 串门 | 跨机验签、加密便签、解密后落任务 |

**第 3 到第 5 项任何一项不过，不能发布。**

## 8. 已知边界（写清楚，不吹）

- 模拟测试在一台机器上用两个独立目录、两个独立进程；物理机那一步必须你自己跑。
- relay 默认是 **HTTP**。跨公网必须上 HTTPS。
- 跨机房间房主需要协作版及以上授权；客人不需要授权码。
- 免费版有本地房间但没有云房间。
- 席位不是无限：`plus` 8 席、`studio` 30 席、`business` 200 席（都含房主）。
- 房间成员默认互相信任，不是多租户隔离。
- 邀请链接本身就是进入凭证。
- 当前房间没有独立的 `send` / `pull` 聊天动作；协作消息通过任务板事件和 `sync` 传递。
- 没有用户第二台物理电脑、公网 HTTPS、跨操作系统或真钱到账的既存验收证据。

## 9. 排障

| 现象 | 先看这里 |
| --- | --- |
| 乙机连不上 relay | 防火墙放行 8787；确认用的是局域网 IP 不是 `127.0.0.1` |
| 建房间被拒/402 | 房主没有有效协作版授权，或档位不含云房间 |
| 进房提示邀请失效 | 链接被 shell 吃掉、抄错，或房主窗口已关 |
| 乙机看到任务、甲机看不到认领 | claim 后两边都要 `sync`，不要只看本地 |
| `room_full` | 席位到上限，不是无限 |
| 串门验签失败 | 邀请和接收不是同一次生成的，别混用 |
| 便签解不开 | 用了自己的 `box`，不是对方的 |

自动化证据写到 `docs/evidence/`；真机测试请额外保存两端完整终端输出。
