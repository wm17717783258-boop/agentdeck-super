# 多设备席位 · 一页纸执行卡

版本：`1.11.4` · 适用：同一局域网内的公司项目验收

## 先定边界

- **能**：一个项目房间，多台物理设备用同一份安装包加入；房主能看到席位名单和任务回流。
- **当前上限**：企业版 `200` 席，房主占 1 席；`--seats 200` 最多再加 199 台。**不是无限席位。**
- **不要宣传**：现在还不能保证所有 Agent 在 GitHub / npm / MCP Registry 搜索到并安装；当前用统一 `.tgz` 分发。
- **不要用** `127.0.0.1` 或 `198.18.0.1` 做跨设备地址。
- **运行环境**：每台设备都要 Node.js `>= 22.12.0`；先执行 `node --version`。

## 每台设备：安装同一份包

把这两个文件放到每台设备：

```text
agentdeck-super-1.11.4.tgz
SHA256SUMS.txt
```

每台设备执行：

```powershell
Get-FileHash .\agentdeck-super-1.11.4.tgz -Algorithm SHA256
New-Item -ItemType Directory -Force C:\nexi | Out-Null
Set-Location C:\nexi
tar -xzf <下载目录>\agentdeck-super-1.11.4.tgz
Set-Location .\package
node .\bin\nexi.mjs doctor
node .\bin\nexi.mjs install --all
```

`doctor` 必须显示 `ok: true`；`install --all` 只接本机已安装的宿主。

## 房主：开一个项目房间

按总设备数选 `N`，N **包含房主**：

```powershell
Set-Location C:\nexi\package
node .\tools\nexi-pair.mjs host --tier business --seats 10
```

例如 10 台设备：房主 1 席，还可加入 9 台。房主窗口不能关；关掉就关房。

输出里必须有：

```text
测试授权：企业版 / 10 席
席位口径：房主占 1 席，最多还可加入 9 台设备
```

## 每台成员设备：加入

把房主给的邀请链接保存到 `invite.txt`，每台设备只改名字：

```powershell
Set-Location C:\nexi\package
notepad .\invite.txt
node .\tools\nexi-pair.mjs guest --invite-file .\invite.txt --name "张三-设计部"
```

成功的唯一标准：输出包含 `进房并同步成功`。每台设备用唯一名字，房主执行：

```powershell
node .\tools\nexi-pair.mjs members
```

公司当前最简分配法：**一个项目房间 + 一条邀请 + 一张“姓名-部门/设备”席位表**。不要给每个部门建不同房间，否则任务板和成员会被拆散。

## 五项物理验收

1. 成员设备执行 `Test-NetConnection <房主局域网IP> -Port 8787`，必须是 `TcpTestSucceeded : True`。
2. 每台设备 `guest` 后，房主 `members` 人数增加；第 N+1 台明确报满员。
3. 房主派一条任务，成员 `sync -> task list -> task claim -> task done -> sync`；房主最终看到 `done` 和成员写的产出。
4. 三台设备同时 `task claim` 同一条任务，只能一台成功。
5. 房主 `Ctrl-C` 后成员 `check` 必须报连不上，但本机任务板不丢；重开 host 是新房间、新邀请。

## 发现问题后的重测闭环

不要直接在解包目录改文件后让所有设备“再试试”。源码修好后：

```powershell
Set-Location <源码目录>
node .\tools\test-summary.mjs
npm pack --pack-destination .
Get-FileHash .\agentdeck-super-1.11.4.tgz -Algorithm SHA256
```

把新 `.tgz` 和新 SHA256 发回所有设备，全部重新解包到新目录再测。这样所有设备测的是同一版。

## 市场安装的真实状态

当前已实测：npm 查询 `agentdeck-super` 是 `E404`，MCP Registry 同名查询 0 条，GitHub 1.11.4 Release 未确认。  
所以现在最稳的不是“搜索安装”，而是共享盘 / 群文件 / 私有 Release 分发同一个 `.tgz`。  
支持 MCP 的宿主可以接；不支持 MCP 的 Agent 需要适配器，不能写成“所有 Agent 自动支持”。
