# 产品蓝图：从"一个超级 Agent"到"Agent 的共同体"

> 初心（你自己说的）：**打破所有 Agent 的孤岛**。
> 三层协同：Agent 与 Agent 协同 → 人与人协同 → 全球人与人的协同。
> 两个抓手：**邀请**（把别人拉进来）、**桌宠串门**（社交化的入口）。
> 一条底线：开源可免费用，钱从"云端的协同"里赚，不从"本地的开关"里赚。

---

## 0. 一句话

> **AgentDeck Super = 让每个人的 Agent 都能互相认识、互相派活、互相串门。**

不是"又一个更强的单 Agent"，是"**Agent 之间的互联网**"。

---

## 1. 四层架构（每一层都能单独上架、单独产生价值）

```
┌─────────────────────────────────────────────────────────┐
│ L4 社交层  桌宠串门 · 公开房间 · 名片 · 邀请海报          │  传播与留存
├─────────────────────────────────────────────────────────┤
│ L3 网络层  身份(Passport) · 邀请(Invite) · 房间(Room)     │  护城河 + 收费点
│            · 中转(Relay) · 跨机器席位(Seat)               │
├─────────────────────────────────────────────────────────┤
│ L2 协同层  角色分工 · 任务板 · DAG · 验收门 · 席位        │  干活
├─────────────────────────────────────────────────────────┤
│ L1 执行层  工具带(文件/命令/检索/网页) · 大脑(host/api/cli)│  底座
└─────────────────────────────────────────────────────────┘
```

**关键取舍**：L1/L2 不跟官方和 20 多个团队插件硬碰，做法是——
- L1 用宿主工具 + 我们自己的沙箱工具带（已实现）；
- L2 **站到官方 Agent Teams 的肩上**：官方管 roster、消息、任务板；我们负责"**让他们能坐进不同家的 Agent**"（provider 适配器）+ 跨机执行（ADBP）。

## 2. 六个核心概念（整个产品的骨架）

| 概念 | 是什么 | 类比 |
| --- | --- | --- |
| **Passport（名片）** | 一个本地生成的身份：`name` + 公钥指纹 + 能力标签（会写代码/会审代码/有 GPU/能上网）。第一次运行自动生成，不需要注册账号 | 微信名片 |
| **Invite（邀请）** | 一条 URL：`dsh://agentdeck/join?token=…`。带过期、带权限（只读/可派活/可接管任务板）、可撤销 | 会议邀请 |
| **Room（房间）** | 一次协作的容器：包含成员、任务板、消息流、产物。可以本地（单人）也可以云同步（多人） | 群 |
| **Seat（席位）** | 一个 Agent 在房间里的位置：既是"成员"也是"工人"。席位可以绑定本机 CLI、远程机器、自研 HTTP Agent | 工位 |
| **Board（任务板）** | 多方共享的真相源：人看板、Agent 领活、完成后过验收门 | 看板 |
| **Visit（串门）** | 你的桌宠带着"一张便签"去对方房间：送产物、要文件、讨个人情（派个活） | 串门 |

一个 Room 的生命周期：`创建 → 邀请（或本地开跑）→ 席位领活 → 任务板推进 → 验收 → 归档/分享海报`。

## 3. 技术方案（够薄、够稳、够省）

### 3.1 三条接入通道（"任何 Agent 都能进组"的实现）

| 通道 | 实现 | 谁用得上 |
| --- | --- | --- |
| **A. 原生 provider 适配器** | 往 `ctx.subagents` 注册一个 provider（官方已支持"外部执行体"：`establishExternalCatalogChild`），把外部 Agent 伪装成原生 teammate | 想直接用官方团队 UI 的人；这是"最顶级"的整合 |
| **B. ADBP（Agent Deck Bridge Protocol）** | 我们自己的 HTTP 协议：`manifest / hello / tasks(长轮询) / result / chat / state`。任何语言 20 行接入 | 自研 Agent、内网 Agent、别人的机器 |
| **C. CLI / ACP / OpenAI / CDP 直连** | 已实现：本机 `claude/codex/dev/gemini`、ACP over HTTP、任意 OpenAI 兼容、桌面 App 走 CDP | 零改造成本接入现有工具 |

A → 官方生态内部；B → 跨组织跨机器；C → 低成本普及。**B 是护城河，A 是体验，C 是获客。**

### 3.2 Relay（中转）怎么做到"不碰数据也能协同"

- 默认 **端到端**：任务摘要、产物清单走 relay；大文件走 P2P（WebRTC 不可用时降级 relay 直传）。
- relay 只存"房间事件流"（谁领了哪块活、结果摘要），不存代码全文 → 隐私友好，成本极低。
- 参考实现就是 `dsh-remote-agent` 的 pairing + relay 思路（已存在，我们做多方版）。
- 部署：一个 Cloudflare Worker + Durable Object（或 Vercel + Postgres），**早期一台机器就够**。

### 3.3 桌宠串门（唯一没人占的空位）

- 39 个桌宠插件都只做"本地宠物"。我们提供 **Visit 协议**：宠物会带着一张 JSON 便签出门。
- 玩法：`pet_visit(roomUrl)` → 对方桌宠收到"有人来做客"，可以：
  - 送一个产物（文件 / 一段总结）
  - 讨一个活（"我这缺个 SQL 审查，帮我派一个席位"）
  - 纯玩：互相留一句涂鸦/表情（留存和传播）
- **为什么它能带来增长**：串门天然需要第二个人的 DSH → 自带邀请属性，是比"注册引导"强十倍的拉新。

## 4. 版本路线（每个版本都能单独上架、单独被理解）

| 版本 | 主题 | 内容 | 上架收益 |
| --- | --- | --- | --- |
| **v1.3.0**（在做） | **超级 Agent + 异构团队** | 四个工具（`super_agent` / `team_orchestrate` / `agent_join` / `team_board`）、工具带、三模式大脑、ADBP 接入、本机 CLI 自动探测 | 免费上架，换第一批用户与 star |
| **v1.4.0** | **邀请协作** | Passport + Invite 链接 + Room 本地/共享 + 任务板多人可见 + 别人的 Agent 通过 ADBP 领活 | 第一次有"必须两个人才能用"的功能 → 拉新 |
| **v1.5.0** | **云中转** | Relay（Cloudflare Worker）+ 跨机器席位 + 断线重连 + 房间归档/海报 | **第一个收费点**：云房间订阅 |
| **v2.0.0** | **串门与网络** | 桌宠 Visit 协议 + 公开房间广场（可选）+ 名片/能力市场 + 企业审计导出 | 订阅 + 团队版 + 定制 |

> 顺序不能颠倒：先让人"一个人就爽"（v1.3），再让人"必须拉人一起爽"（v1.4），再让"拉人这件事收钱"（v1.5），最后"社交网络"（v2.0）。

## 5. 赚钱：最简单的那条路（三步，不需要先建网站）

### 第 0 步（0 成本，今天就能做）
- 开源 MIT + 免费上架市场 → 换流量。
- 收钱方式：**卖"云房间邀请码"**（人工发码也行）。工具：爱发电 / 小报童 / 知识星球 / 微信收款码。
- 定价：`¥29/月` 一个云房间（5 席位、任务板云同步）；`¥299/年`；团队 `¥199/月`（10 席位 + 审计导出）。

### 第 1 步（两天工程量）
- 一个 Worker：`/v1/activate`（码换 token）+ `/v1/rooms`（房间、席位、事件流）+ `/v1/quota`。
- 插件里只做一件事：**没 token 就只能本地房间**；有 token 才能跨机。→ 收费点天然在服务端，破解本地代码没用。

### 第 2 步（真有人按月付了再做）
- 自助下单页（静态页 + 上述接口）、发票、团队席位管理、用量看板。
- 这时才需要域名和网站，而且只是一个静态页 + 三个 API。

**为什么不卖"本地功能解锁"**：插件在用户机器上以用户权限运行，任何人改两行 JS 就破了。**唯一拦得住的是我们不给他、而服务器才有的东西。**

**第二条收入线（更省事）**：把 v1.5 的 relay 做成"托管版"，按房间/月收费给公司内网团队用；同时卖"私有化部署 + 接入培训"（你现在 AgentDeck 桌面版正好是企业版入口）。

## 6. 成功怎么衡量

- 北极星：**每周"跨人协同"的房间数**（不是安装量 —— 安装量可以刷，跨人协同刷不出来）
- 二级：邀请链接发出数 / 接受率（目标 > 30%）、每房间平均席位数、串门次数
- 三级：留存（7 日回访）、付费转化（目标 2~4%）、ARPU

## 7. 明确不做的事（防止摊子铺太大）

1. 不做自己的模型、不做自己的 IDE。
2. 不跟官方 Agent Teams 抢"团队内核"，只做它缺的异构与网络。
3. 不做公共社交广场（v2.0 之前），先把"两三个人协同"做扎实。
4. 不碰用户代码内容上云（只走摘要 + 产物清单）。

## 8. 现在这一步和蓝图的关系

正在写的 `lib/` 就是 **L1 执行层 + L2 协同层的骨架**（工具带、任务板、ADBP、三模式大脑、四个工具），
它是 v1.3 的交付物，也是 v1.4 邀请协作的地基——邀请进来的人，最终领的就是这张任务板上的活。
蓝图里 v1.4 的所有新概念（Passport / Invite / Room / Seat）都会以**新增模块**的方式叠加，不推翻已写的代码。
