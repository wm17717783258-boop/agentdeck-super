# 1.11.17 —— 不分 Agent：接入能力交到用户手里

**一句话**：以前"支持哪些 Agent"是一张写死在代码里的名单，加一家要发一次版。这版改成三层：内置 25 家、用户自己写一行就能加、实在不行生成片段粘进去。**任何吃 MCP 的 Agent 都能接，不用等我们。**

## 一、为什么改

Agent 冒出来的速度比发版快。名单式适配永远慢半拍，而且用户手里那个 Agent 一旦不在名单里，就只能等。所以「适配所有 Agent」不能靠堆名单，得靠**接入通道**。

## 二、三层接入

| 层 | 怎么用 | 谁维护 |
| --- | --- | --- |
| ① 内置 25 个 | `nexi install --all` | 我们，随版本更新 |
| ② 注册表 | `nexi host add <id> <配置文件> [--shape …]`，或直接丢 JSON 进 `$DSH_HOME/agentdeck-super/hosts.d/` | 用户，**不用发版** |
| ③ 兜底片段 | `nexi snippet --shape mcpServers\|servers\|context_servers\|mcp.servers\|mcp.local\|mcp.stdio\|amp.mcpServers\|toml` | 用户复制粘贴 |

还有一条临时通道：`nexi install custom <文件> --shape <形状>` —— 连注册表都不用写，一次装完。

### 内置表从 13 家扩到 25 家

新增：Roo Code、Kilo Code、Kilo CLI、Kiro、LM Studio、Factory Droid、JetBrains Junie、Qoder、Google Antigravity、Amazon Q Developer、Amp、Crush。

配置形状新增三种（都是官方文档核过的，不是猜的）：

| 形状 | 长什么样 | 谁在用 |
| --- | --- | --- |
| `mcp.local` | `mcp.<名字>`，`command` 是数组，`environment` | Kilo CLI |
| `mcp.stdio` | `mcp.<名字>`，`type:"stdio"` + `command` 字符串 | Crush |
| `amp.mcpServers` | 键名本身带点 | Amp |

## 三、这版修掉的真缺陷

1. **`mcp.*` 形状卸载等于没卸**：这两个形状的写入是"合并"，删除时也走合并 → `nexi uninstall` 报成功、文件里 `mcp.nexi` 还在。现在给形状加了显式 `remove`，并测了安装→卸载往返。
2. **OpenCode 在 Windows 上被写进 `%APPDATA%`**：它三系统都读 `~/.config`，跟着 `%APPDATA%` 走会写到一个它永远不看的地方。新增 `xdgRoot()` 区分「XDG 语义」和「应用配置语义」。
3. **doctor 被 25 个宿主顶爆**：一家一行"没装，跳过"把结论挤出屏幕（回归测试 `lines <= 45` 当场变红）。改成：装了的逐条列，没装的折成一行。
4. **Antigravity 路径算成 `AppData`**：`dotConfigRoot/..` 这种拼法在该目录不存在的系统上会歪，改成明确的家目录路径。

## 五、边界（不改口）

- **没有第二台 Mac / Linux 真机**。矩阵测试锁的是路径算得对，锁不住"真 Mac 上点开宿主看见 23 个工具"。
- 25 家里，本机只装了 6 家（Claude Desktop / Claude Code / Codex / Gemini CLI / Qwen / Copilot CLI），其余 19 家的路径与形状来自官方文档核对，**没有在真宿主上点开验证**。
- 明确不支持的形态：Warp（没有可写配置文件，只能 UI 里粘片段）、Goose（YAML）、Continue 新格式（YAML）—— 前者用 `nexi snippet` 兜底，后两个等 YAML 写入器。
- npm 未发布，等你点头。
