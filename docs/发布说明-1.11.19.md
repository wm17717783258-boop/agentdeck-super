# Nexi 1.11.19

> 这一版回答两件事：**「插件到底分不分系统」**，以及 **「体检报告会不会骗人」**。
> 前者用一条会红的测试钉死，后者修掉了一个会让人白查半天的假绿。

## 一、一个包，不分系统 —— 从"我保证"变成"你验"

上一版把路径按三系统算对了，但一直在用"三张表""平台矩阵"解释，听起来还是分系统。
这一版换了个说法，也换了做法：**把"不分系统"写成测试，谁破坏谁红。**

新增 `tests/one-package.test.mjs`（7 条）：

| 断言 | 说明 |
| --- | --- |
| `package.json` 不许有 `os` / `cpu` / `optionalDependencies` / `dependencies` | 有任何一个，npm 就可能拒绝平台或引入原生模块 |
| 仓库里不许有 `.node` / `.exe` / `.dll` / `.dmg` / `.msi`，根目录不许有 `install.ps1` / `install.sh` | 有就是"平台专属产物"回潮 |
| **平台分支白名单** | 只有 9 个文件允许出现 `process.platform`，每个都写明理由；白名单外的文件出现平台判断立刻红 |
| 白名单不许腐烂 | 白名单里的文件如果已经没有平台分支，也红 —— 逼着人删掉过期条目 |
| 三系统配置**结构同构** | 8 种 JSON + 2 种 YAML 形状，在 win32/darwin/linux 下生成的键名、层级、数组长度必须逐字相等，只有路径字符串不同 |
| MCP 服务端零平台判断 | `lib/mcp/**` 里出现 `process.platform` 就红 |
| 每个宿主在三系统都能算出绝对路径且互不相同 | 顺带守住"darwin/linux 不许出现 AppData 或反斜杠" |

**突变验证**：往 `package.json` 注入 `os: ["win32"]`、`cpu: ["x64"]`、`dependencies: {"node-windows":"^1"}`，第 1 条立刻红；还原后绿。

真实事实（可以直接查）：
- `npm i -g agentdeck-super` 在三个系统下是**同一个 tarball、同一份字节**；
- 零运行时依赖，没有一个原生模块；
- 安装动作只有 `nexi setup` 一条，没有分平台的安装脚本；
- 唯一"按系统"的是**宿主自己把配置文件放在哪**（Windows 在 `%APPDATA%`，macOS 在 `~/Library/Application Support`，Linux 在 `~/.config`）—— 那是别人的目录习惯，不是我们的分支。

## 二、体检不再说谎（本版最重要的一处）

原来的判据只有一行：

```js
/nexi/i.test(readFileSync(host.path, 'utf8'))
```

它在这些情况下都给绿勾：

- 条目指向的脚本**已经被删/被移动**（换了 `NEXI_HOME`、清了 Temp、删了旧版本）
- `command` 写的 node 路径**不存在**（nvm 切版本、卸载重装）
- 只是**注释**里提到 nexi（TOML 的 `# nexi`、YAML 的注释行）
- 别家 server 名字里带 nexi（`nexi-helper`、`my-nexi`）
- 条目是 `null` 或空对象

假绿比红更糟：用户看到 ✅ 就不查了，然后在宿主里怎么都连不上。

新增 `lib/connect/audit.js`，改成**四层校验**：

1. **结构** —— 按宿主自己的形状真的解析出 `nexi` 这一项（`mcpServers` / `servers` / `context_servers` / `mcp.servers` / `mcp.local` / `mcp.stdio` / `amp.mcpServers` / TOML 哨兵块 / YAML 两种写法）；
2. **目标** —— 条目里的脚本路径在磁盘上存在；
3. **解释器** —— `command` 是绝对路径就查存在，是裸名就查 PATH（含 `PATHEXT`）；
4. **一致** —— 路径与当前这份不同就记一句备注（不判故障，多副本可能是有意的）。

状态从两个（true/false）变成五个：`wired` / `unreachable` / `absent` / `broken` / （备注）。

`doctor` 的 `--json` 输出里，`hosts` 检查**不再写死 `ok: true`** ——
装了但接不上就是 FAIL，并把原因与下一步写进 `auditReason`。

`tests/host-audit.test.mjs`（16 条）把上面每种假绿场景都做成用例。
静态防线那条会盯着 `bin/nexi.mjs` 里 `name: 'hosts'` 那一段，谁改回 `ok: true` 谁红。

## 三、并发写同一份配置不再丢更新

以前 `install` / `uninstall` 是"读-改-写"三步，中间没有互斥。
两个终端同时跑 `nexi install --all` 和 `nexi install codex`，后写的会把先写的整段抹掉 ——
而且**不报错**，这类丢更新最难查。

新增 `lib/connect/lock.js`：
- 用 `openSync(file, 'wx')` 建锁文件（三系统都原子，Node 没有跨平台 flock，这是最稳的）；
- 锁里写 `pid` 与时间，超过 30 s 或持锁进程已死 → 允许抢占；
- 只包**落盘那几毫秒**，不包探测 —— 否则 `--all` 会自我串行化；
- 拿不到锁超时 → 返回 `lock-timeout` 并把持锁 pid 告诉用户，不抛栈；
- 目录不可写 → 降级为无锁执行，不让"整个装不上"。

`tests/lock-backup.test.mjs` 里有一条**开两个真进程**同时往一个文件装不同条目的用例，
断言两家的条目最后都在。把锁去掉这条立刻红。

## 四、备份不再变成垃圾，而且能回滚

以前只有"写前备份"这一半：每次安装留一个 `.nexi-backup-<时间戳>`，**从不清理**。
装 10 次 26 家就是几百个文件堆在用户配置目录里 —— 这不叫安全，叫倒垃圾。
另一半也缺：有备份却只能自己去目录里翻。

新增 `lib/connect/backup.js` + `nexi restore`：

```bash
nexi restore                # 列出所有"有备份可回"的宿主
nexi restore codex          # 这个宿主有哪些备份（时间、来由、大小）
nexi restore codex --last   # 回滚到最近一份
nexi restore codex --to <文件>
nexi restore codex --last --dry-run
```

- 每个配置文件只留**最近 5 份**（上限 20，`keep: 0` 也至少留 1 份 —— 永远留一条退路）；
- 回滚前会把"现在这份"存成 `.prerestore` —— **回滚本身可撤销**；
- 回滚后**回读比对字节**，不信任 `copyFileSync` 的返回值。

## 五、`nexi doctor --export`：出问题能一条命令导出脱敏现场

```bash
nexi doctor --export              # 在当前目录生成 nexi-diag-<时间戳>/
nexi doctor --export --out ~/桌面
```

9 个纯文本文件：`README.txt` / `meta.json` / `doctor.txt` / `hosts.json` /
`config-shapes.json` / `backups.json` / `locks.json` / `state.json` / `logs.tail.txt`。

**红线：不导密钥、不导配置原文。** 配置只导结构（有哪些键、`nexi` 在哪一层、字段名、多大），
家目录一律缩成 `~`，状态目录只列文件名与大小。

`tests/diagnostics.test.mjs`（8 条）里有一条是拿**本机真实配置**跑一遍，
全目录搜 `sk-*` / `ghp_*` / 40 位十六进制 / JWT，断言一个都搜不到。

## 六、顺手修的三个真缺陷

1. **`--name` 在写配置文件那条路上静默失效**。`nexi install custom <文件> --name alpha`
   以前只有"走宿主 CLI"那条路认 `--name`，写文件那条硬编码 `nexi` ——
   于是同一个 Agent 里装两份必然互相覆盖。现在 `planJson` / `planToml` / `planYamlHost` /
   `removeFromJson` / `planYamlRemove` 全部贯通 `name`；TOML 只有一种块名，传别的名字时直接拒绝，不偷写。
2. **同一毫秒内的多次备份互相覆盖**。`--all` 批量备份或测试循环里，文件名只到毫秒，
   撞名就覆盖 —— 等于把上一份备份吃掉，正是备份最不该犯的错。现在撞名加序号 `-2`、`-3`，
   `parseBackupName` 能倒推出 `seq`。
3. **`restoreHost` 不认 `--path` / 临时宿主**。`nexi install custom` 写进去的自定义 Agent 无法回滚，
   因为 `restoreHost` 只查内置表。恢复只需要"文件在哪"，现在给了 `--path` 就能回滚任意文件。

## 八、边界（不改口）

- **26 家里本机只真装过 6 家**。其余 20 家是文档级适配，代码能生成正确配置，但没在真宿主里点开过。
- 仍没有第二台 Mac / Linux 真机。`one-package` 锁的是"算得对、结构一致"，锁不住"真 Mac 上点开看见 23 个工具"。
- YAML 只覆盖块状 map / 块状 seq / 流式数组；锚点、别名、多文档 `---` 遇到会拒绝改写（不猜）。
- 并发锁是**单机**语义。两台机器同时写同一个网络盘上的配置，不在保护范围。
- npm 仍未发布 1.11.19；只在 GitHub 与本机固定目录。
