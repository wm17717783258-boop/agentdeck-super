> 当时打印的邀请链接也可能是 `127.0.0.1`。现行流程只有一份：[`装机和多设备测试.md`](装机和多设备测试.md)。

>
> 当前版本：`1.11.4`。当前席位口径：默认协作版 8 席；多设备项目测试必须显式写

## 前置（两台都要）

1. **Node.js >= 22.12** —— 敲 `node --version` 确认
2. **两台在同一个 WiFi / 同一交换机下**
3. **同一份代码** —— 把整个项目目录拷到两台设备（U 盘 / 微信 / 网盘 / git clone 都行）

> 拷过去之后，两台各自进到项目目录里。

---

## 第一台设备（房主）

```bash
node tools/nexi-pair.mjs host --tier business --seats 10
```

它会自动做完四件事：

1. 找出本机最该用的局域网地址（自动跳过 VMware / WSL / 回环那些连不通的网卡）
2. 起一个中继（relay）并绑到 `0.0.0.0`（别的设备才连得上）
3. 生成一张测试用授权码并激活（**不用你去 license-cli 手工发码**）
4. 建好房间，打印出**可以整段复制发出去**的文本块

输出长这样：

```
===== 复制下面整段发给成员设备 =====
中继地址：http://192.168.1.10:8787
邀请链接：dsh://agentdeck/join?room=xxxx&t=yyyy

成员设备上执行（把邀请存到 invite.txt，名字改成员工自己的）：
① node tools/nexi-pair.mjs guest --invite-file invite.txt --name "张三-设计部"
===== 复制结束 =====

房间已建好，中继在这个进程里跑着 —— 别关这个窗口。
```

**把这个窗口留着别关。** 关了 = 房间没了。

## 第二台设备（客人）

**先看这条警告**：邀请链接里有 `&`，在 cmd / PowerShell 里 `&` 是命令分隔符。
直接 `--invite "http://x/?room=a&t=b"` 时，双引号可能被 shell 吃掉，
结果 `&t=b` 变成另一条命令 —— 插件收到残缺链接，报「邀请已失效」。
**看着像插件坏了，其实是 shell 干的。** 所以用下面三种方式之一：

**方式 ① 存成文件（最稳，推荐）**

```bash
# 把邀请链接存到 invite.txt（记事本、echo 都行）
node tools/nexi-pair.mjs guest --invite-file invite.txt --name "张三-设计部"
```

**方式 ② 环境变量**

```bash
# cmd
set NEXI_INVITE=http://192.168.1.10:8787/?room=xxxx&t=yyyy
node tools/nexi-pair.mjs guest --name "张三-设计部"

# PowerShell
$env:NEXI_INVITE="http://192.168.1.10:8787/?room=xxxx&t=yyyy"
node tools/nexi-pair.mjs guest --name "张三-设计部"

# bash / zsh / macOS / Linux
export NEXI_INVITE="http://192.168.1.10:8787/?room=xxxx&t=yyyy"
node tools/nexi-pair.mjs guest --name "张三-设计部"
```

**方式 ③ 直接贴（bash/zsh 没问题，cmd 容易踩坑）**

```bash
node tools/nexi-pair.mjs guest --invite "http://192.168.1.10:8787/?room=xxxx&t=yyyy" --name "张三-设计部"
```

它会：

1. 进房间；
2. 调用一次 `sync` 完成报到并拉取房间任务；
3. 提示你下一步。

**客人不需要授权码。** 这是设计。

## 两边各自核对

两台都可以敲（PowerShell）：

```powershell
node .\tools\nexi-pair.mjs check
node .\tools\nexi-pair.mjs sync
```

输出包含：

- 中继可达性（连不上会直接告诉你"房主那边窗口是不是关了"）
- 本机任务板摘要
- 房间状态和成员
- 最近同步结果

**两边看到同一个房间和同一批任务 = 跨机协作通了。**

## 想看"我该填哪个地址"

任何一台都可以先跑：

```bash
node tools/nexi-lan.mjs
```

它会列出本机所有地址并标出该用哪个：

```
本机可用地址：
  [局域网]    192.168.1.10    WLAN   <= 用这个
  [局域网]    198.18.0.1       Meta
  [虚拟网卡]  192.168.13.1     VMware Network Adapter VMnet1
  [仅本机]    127.0.0.1        Loopback Pseudo-Interface 1
```

如果只有 `127.0.0.1`，它会明确告诉你"别的设备连不上，先接 WiFi"——不假装有局域网。

## 手机也能参与（加入页）

手机上跑不了 node，但能开浏览器。在第一台设备上：

```bash
node tools/nexi-lan.mjs --serve
```

它会给一个地址，比如 `http://192.168.1.10:8788/`。

**用手机浏览器打开它**，页面上有：

- 配对码（和终端里一致，便于两边对暗号）
- 中继地址（可一键复制）
- **「测试连接」按钮** —— 点了就知道手机能不能连上中继
- 接下来三步的操作说明

还有个纯文本版，方便直接复制到微信：`http://<地址>:8788/handoff`

## 三台及以上

第一台照上面跑 `host`。

第二台、第三台、第四台……都用**同一条邀请链接**跑 `guest`，但每台要带唯一 `--name`，且席位有上限：

| 档位 | 席位上限（含房主） | 云房间 |
| --- | ---: | ---: |
| 免费 | 3 | 0 |
| 协作版 `plus` | 8 | 20 |
| 工作室版 `studio` | 30 | 50 |
| 企业版 `business` | 200 | 200 |

`nexi-pair host` 不带参数时自动签 8 席协作版测试授权，所以默认最多 8 台设备（含房主）。
要做大型项目验收，房主显式执行 `host --tier business --seats N`；企业版硬上限 200 席。
超过上限 relay 返回 `room_full`，不是“无限客人”。

公司当前最简分配方式：一个项目房间、一条邀请链接、一张“姓名-部门/设备名”席位表；
每台设备用不同 `--name` 占 1 席，房主用 `members` 核对名单。当前不能按员工单独签发/撤销。

然后验证"任务不会被重复领"：

```powershell
# 房主加一条任务
node .\bin\nexi.mjs call team_board '{"action":"add","title":"只该被一个人领"}'

# 两台同时抢（各自执行）
node .\tools\nexi-pair.mjs task list
node .\tools\nexi-pair.mjs task claim --id <任务号>
```

**只有一个能抢到**，另一个会拿到"已被认领"。抢完两边都要 `sync`，房主才能看到 `running`。

### 任务完成的真实验收

房主：

```powershell
node .\tools\nexi-pair.mjs task add --title "跨机验收任务" --acceptance "对方看到并领取"
node .\tools\nexi-pair.mjs sync
```

客人：

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
node .\tools\nexi-pair.mjs task claim --id <任务号>
node .\tools\nexi-pair.mjs sync
```

房主确认状态：

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

客人完成：

```powershell
node .\tools\nexi-pair.mjs task done --id <任务号> --output "已完成"
node .\tools\nexi-pair.mjs sync
```

房主再次确认 `done` 和产出。房主看不到回传 = 验收失败。

## 跨公网（不在同一网络）

局域网用 `http://` 就行。跨公网必须 HTTPS，两种做法：

**做法一：relay 自己带证书**

```bash
node tools/make-cert.mjs --host <你的域名或公网IP>
node tools/relay-server.mjs --port 8787 --host 0.0.0.0 --data .relay-data --tls-cert certs/cert.pem --tls-key certs/key.pem
```

**做法二（推荐）：前面挂一层反代**

relay 只在内网端口跑 HTTP，Nginx/Caddy 挡在前面做 TLS。Caddy 最简单：

```
nexi.example.com {
  reverse_proxy 127.0.0.1:8787
}
```

然后建房间时把地址换成公网的：

```bash
node bin/nexi.mjs call deck_room "{\"action\":\"create\",\"name\":\"异地\",\"relayUrl\":\"https://nexi.example.com\"}"
```

> `relayUrl` 是这次新加的能力：**以前只能改配置文件**，现在命令行里直接指定。
> 长轮询要放宽反代超时（`proxy_read_timeout 300s`），不然 sync 会被切断。

## 出问题怎么办

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 第二台 `guest` 报连不上 | 不在同一 WiFi | 连同一个 WiFi / 手机热点 |
| 同上 | 房主防火墙挡了 8787 | Windows 会弹窗选"允许"；或手动放行 8787 |
| 同上 | 房主用了虚拟网卡地址 | 跑 `node tools/nexi-lan.mjs` 看它选了哪个 |
| `check` 说中继连不上 | 房主窗口关了 | 重新跑 `host`（房间会重建） |
| 第二台能连上但进不去房间 | 邀请链接过期/抄错 | 让房主重跑 `host`，复制新的整段 |
| 只有 `127.0.0.1` | 没连网 | 接 WiFi 或网线 |
