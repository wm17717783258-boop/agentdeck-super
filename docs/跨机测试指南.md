两台电脑怎么测这个插件（1.10.0）
==================================

先说结论：**跨机能力是真的，不是演示**。
已在一台物理机上用"两个独立进程 + 走局域网真实地址"跑通全链路
（证据：docs/evidence/crosshost-1.10.0.txt，25 项全过）。
下面是你在**两台真电脑**上的操作步骤。

────────────────────────────────────────────────────────────
第 0 步：插件到底怎么"装"
────────────────────────────────────────────────────────────
这个插件有**两个身份**，对应两种装法：

  身份 A：DSH 插件
      dsh plugin --profile <名字> add <tgz 或包名>
      —— 在 DSH 里用。

  身份 B：MCP server（**装进别的 Agent**）
      别的 Agent 通过 stdio 起：node <插件目录>/bin/nexi.mjs mcp
      —— Claude Code / Codex / Cursor / Windsurf / Cline / Continue /
         Gemini CLI / Claude Desktop 都是这一种。

  不想手写配置？一条命令生成：
      nexi config codex        # 给出 Codex 的配置
      nexi config --all        # 8 个宿主一次给全
      nexi config cursor --out c.json
  **生成配置不需要装那个宿主** —— 适配靠的是知道它的配置格式。

────────────────────────────────────────────────────────────
第 1 步：两台电脑都装好
────────────────────────────────────────────────────────────
在**每台**电脑上：

  1) 装 Node 22.12+（engines 要求）
  2) 拿到插件（三种途径任选）：
       · 从 GitHub clone：git clone https://github.com/wm17717783258-boop/agentdeck-super
       · 或拷贝打包好的 agentdeck-super-1.10.0.tgz 过去，npm i -g ./agentdeck-super-1.10.0.tgz
       · 或 npm i -g agentdeck-super（等发布后）
  3) 装进你要用的 Agent：
       nexi install --all              # 探测到哪个装哪个
       nexi install codex              # 只装 Codex
       nexi install codex --dry-run    # 先看会写什么
  4) 让宿主自己确认装上了：
       claude mcp list      → nexi: √ Connected
       codex mcp list       → 列表里有 nexi
       gemini mcp list      → Configured MCP servers: ○ nexi

  两台都做完，才能进下一步。

────────────────────────────────────────────────────────────
第 2 步：先测**单机**功能（不依赖网络）
────────────────────────────────────────────────────────────
在任一台的 Agent 里说这些话，看它是不是真调了工具：

  「用 team_board 建一个小组，叫 联调测试」
  「记一条：我的项目用 pnpm」
  「用 twin_recall 把我刚记的找回来」        ← 写→读闭环
  「用 pet_skin 列出皮肤，然后换上水墨」
  「用 deck_meeting 开一场会，议题写 联调」
  「用 deck_audit 看看我刚才做了什么」       ← 审计真的记了
  「用 deck_policy 写一条规则：pet_skin 要确认」
  「用 deck_market catalog 看货架」

  单机全通 = 插件装对了。

────────────────────────────────────────────────────────────
第 3 步：测**串门**（两台电脑之间，不需要服务器）
────────────────────────────────────────────────────────────
串门是一对一的，靠"人传一条链接"，**不用起任何服务**。

  电脑 A：
    「用 pet_visit action=invite 给我一张邀请函」
    → 它给你一条 dsh://agentdeck/visit?t=xxxx 的链接（很长）
    把这条链接**发微信/邮件**给电脑 B

  电脑 B：
    「用 pet_visit action=accept，token 是 <粘贴那一长串>」
    → B 会显示 A 的名片，并验签

  然后 B 给 A 留一张带加密的求助便签：
    「用 pet_visit action=ask，标题写 帮我看下报表，
       box 填 <accept 输出里给的那个 box 值>」
    → 输出的 JSON 是**密文**（明文一个字都不在里面）
    把那段 JSON 发给 A

  电脑 A：
    「用 pet_visit action=receive，note 是 <粘贴那段 JSON>」
    → A 解出明文，并且**真的落成一条任务**

  验证点：改一个字符就验不过；过了有效期也验不过。

────────────────────────────────────────────────────────────
第 4 步：测**跨机房间**（多台电脑协作，需要 relay）
────────────────────────────────────────────────────────────
这条路要一个中转服务器（relay）。两种做法：

  【做法一】A 机当服务器（局域网够用，推荐先这么试）
    A 机上跑：
      node tools/relay-server.mjs --port 8787 --host 0.0.0.0
    → 它会打印：
        → 别的电脑填这个：http://192.168.x.x:8787
    记下这个地址。**Windows 防火墙可能要放行 8787 端口。**

  【做法二】放到公网服务器上（跨网络用）
      同上命令丢到一台有公网 IP 的机器
      ⚠️ 必须套 HTTPS 反代（relay 自己只讲 HTTP，公网不加密等于裸奔）

  然后两台电脑都要填 relay 地址：
    在插件配置里设 cloud.relayUrl = http://192.168.x.x:8787
    或者 <工作区>/.agentdeck/ 下的配置里改。

  注意：**跨机房间是「协作版」（¥29/月）起的能力**。
  免费版只能用本地房间。授权码在这里粘贴：/deck 状态页。

  接着：
    电脑 A：「用 deck_room action=create name=联调房间」
            → 拿到房间号和一条邀请链接
    把邀请链接发给电脑 B

    电脑 B：「用 deck_room action=join，roomId=xxx，inviteToken=xxx」
    电脑 A：「用 deck_room action=sync」
    电脑 B：「用 deck_room action=sync」
            → 两边应该看到同一个房间、同样的事件

    之后任务板上的活就能跨机领：一台派活，另一台领走。

────────────────────────────────────────────────────────────
第 5 步：三台 Agent 开会（跨机也行）
────────────────────────────────────────────────────────────
  「用 pet_meeting，topic 写 联调评审，rounds 2，maxTasks 3」
  → 每个参与方的 Agent 各交意见 → 出决议 → **真的落成任务**

  —— 读回来有 abc 才算真加上。

────────────────────────────────────────────────────────────
已知边界（照写，不美化）
────────────────────────────────────────────────────────────
  · 跨机房间要**协作版授权码**；免费版只有本地房间。
  · relay 自己是 HTTP，公网部署**必须**套 HTTPS。
  · 8 个宿主里，本机真装过 4 个；另外 4 个（Cursor/Windsurf/Cline/Continue）
    只验了配置格式对不对，没验过宿主认不认——因为本机没装它们。
  · 支付链路通，但**没有真实商户号**，「真钱进账」这条还开着。
  · 3D / VR / 自有大模型 / 区块链：不做（产品方案里明确划掉了）。
