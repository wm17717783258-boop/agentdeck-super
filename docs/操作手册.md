# Nexi 灵犀 · 完整操作手册

> 面向：你自己（开发者/运维）。从零开始，每一步都能照抄。
> 原则：**能跑通才写进来，跑不通的标「未验」**。

---

## 1. 先决条件

| 项 | 要求 | 怎么查 |
| --- | --- | --- |
| Node.js | **>= 22.12** | `node --version` |
| 操作系统 | Windows 10/11、macOS、Linux | — |
| 磁盘 | 约 50 MB（含依赖与证据） | — |
| 网络 | 单机功能**完全离线可用**；跨机协作需要两台能互通的机器 | — |
| 可选 | DeepSeek Harness（`dsh`）—— 只有"装进 DSH 宿主"那部分需要 | `dsh --version` |

**没有 dsh 也能用**：插件本身就是个 MCP 服务，任何支持 MCP 的宿主都能接。

```bash
node --version    # 必须 >= v22.12.0
```

## 2. 装到本机（单机自用）

### 2.1 固定目录安装（推荐）

任意 MCP 宿主，一条命令装到固定目录，并把稳定启动器写进本机已探测的宿主：

```powershell
node install.mjs
node install.mjs --bundle .\agentdeck-super-1.11.5.tgz
```

装完验证：

```powershell
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" doctor
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" status
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" pair help
```

只在 DSH 里用时，也可以用 DSH 插件入口（npm 上架后）：

```bash
dsh plugin add agentdeck-super
```

### 2.2 从 tgz 装（本地包，测试期用这个）

```bash
# 1) 打一个包
npm pack --pack-destination .
# 产出 agentdeck-super-1.11.5.tgz

# 2) 装进 DSH
dsh plugin --profile web add ./agentdeck-super-1.11.5.tgz

# 3) 重启 DSH，然后
/deck
```

### 2.3 不装 DSH，当独立 MCP 服务用

```bash
# 解包
mkdir C:\nexi && cd C:\nexi
tar -xzf <你拷来的>/agentdeck-super-1.11.5.tgz
cd package

# 看它能提供什么
node bin/nexi.mjs list

# 体检（Node 版本/配置目录/能否起来/认出哪些宿主）
node bin/nexi.mjs doctor
```

**期望**：`list` 打印 23 个工具；`doctor` 全绿。

## 3. 接进各个宿主

### 3.1 一条命令装进所有探测到的宿主

```bash
node bin/nexi.mjs install --all
```

它会：探测 8 个宿主（Claude Desktop / Claude Code / Cursor / Windsurf / Codex / Cline / Continue / Gemini CLI）
→ 只装**探测到的那些** → 写配置前自动备份 → 可一键还原。

### 3.2 装单个 + 验证

```bash
# 装某一个
node bin/nexi.mjs install cursor

# 让宿主自己自证（装 → 调 → 卸 → 配置逐字节还原）
node bin/nexi.mjs verify-host claude-code
node bin/nexi.mjs verify-host --all --record
```

**注意**：`verify-host` 会真的写宿主配置再还原。虽然它有备份，但别在正在用的宿主上跑。

### 3.3 手动接进任何 MCP 宿主

配置里写这一条就够：

```json
{
  "mcpServers": {
    "nexi": {
      "command": "node",
      "args": ["<解包目录>/package/bin/nexi.mjs", "mcp"]
    }
  }
}
```

**只读模式**（借给别人用时不让他改东西）：

```json
{ "args": [".../bin/nexi.mjs", "mcp", "--read-only"] }
```

或设环境变量 `NEXI_MCP_READONLY=1`。

### 3.4 任何支持远程 MCP 的客户端：`nexi serve`

本地 Hub 也可以作为独立 HTTP 服务跑起来，远程 MCP 客户端填 URL 即接：

```powershell
# 本机默认：127.0.0.1:8790，不设 token
node bin/nexi.mjs serve

# 指定端口/地址 + 手动 token
node bin/nexi.mjs serve --host 127.0.0.1 --port 8790 --token <你的token> --read-only
```

端点：`/mcp`（也兼容 `/v1/mcp`、`/adbp/v1/mcp`、`/adbp/mcp`），健康检查 `/healthz`。

**安全规则**：绑定非回环地址或走公网隧道时必须有 token；没给会自动生成并打印。
客户端请求带 `Authorization: Bearer <token>`；`--read-only` 会把写动作全部拒掉。

跨网络三种方式：

```powershell
# 已有反代/隧道域名：先保证它真的回源到本机 serve 端口
node bin/nexi.mjs serve --public-url https://你的域名

# 自动启动 Cloudflare Quick Tunnel（需安装 cloudflared）
node bin/nexi.mjs serve --tunnel cloudflared

# 自动选择可用隧道（cloudflared -> localtunnel）
node bin/nexi.mjs serve --public
```

命令只有看到公网 `/healthz` 返回 200 才会给出公网 MCP URL；失败会打印具体原因和安装提示。

**公网复验（一条命令）**：

```powershell
node tools\verify-public.mjs --provider cloudflared
```

它会本机起 MCP + 公网隧道，从公网侧验 `/healthz`、无 token 401、Bearer 握手、
`tools/list`，四项全过才打印 `PASS`。证据写到 `docs/evidence/public-<版本>.txt`。
2026-11-08 在 Windows + cloudflared 上实测通过（`docs/evidence/public-1.11.2.txt`）。

## 4. 两台电脑协作（重点）

> 这一节是你最关心的。先在本机跑自动化，再上两台物理机。
>
> 真机主路径只推荐 `nexi-pair`：它把地址选择、relay、测试授权、房间和任务小组绑在一起。手工 `deck_room` 只用于排查。

### 4.1 本机自动化基线

```powershell
Set-Location .\package
node .\tools\verify-twomachines.mjs
```

它在一台机器上起两个独立进程、两套独立状态目录，通过真实 relay 走完整流程。

**期望输出**：`28 项通过，0 项失败`。覆盖：

| 验的东西 | 说明 |
| --- | --- |
| 两个独立身份 | 各自状态目录和小组 |
| 甲机建房间 | 使用测试授权 |
| 乙机凭邀请进房 | **客人不需要授权码** |
| 任务同步 | 任务新增、认领、完成回传 |
| relay 重启 | 房间数据仍在 |
| 跨机加密串门 | 邀请→验签→AES 便签→解密→落成任务 |

> 这是同机双进程基线，不是第二台物理机验收。物理机结果必须另跑。

### 4.2 准备交付包

> 安装后的稳定写法是 `node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" pair ...`。
> 下面保留 `tools/nexi-pair.mjs` 的源码目录写法，方便开发验收；两种写法等价。

```powershell
Set-Location "C:\Users\LENOVO\Documents\Codex\2026-11-07\d-y\work\nexi\Nexi灵犀-完整项目"
npm pack --pack-destination .
```

把 `agentdeck-super-1.11.5.tgz` 拷到两台电脑。不要用旧包代替本轮打包结果。

### 4.3 电脑甲（房主）

**① 解包并体检**

```powershell
New-Item -ItemType Directory -Force -Path C:\nexi-A | Out-Null
Set-Location C:\nexi-A
tar -xzf <拷来的>\agentdeck-super-1.11.5.tgz
Set-Location .\package
node .\bin\nexi.mjs list        # 应打印 23 个工具
node .\bin\nexi.mjs doctor
```

**② 一条命令起 relay + 测试授权 + 房间**

```powershell
node .\tools\nexi-pair.mjs host --tier business --seats 2
```

它会自行生成本次配对专用的企业版测试授权（2 席）、启动 relay、建小组和房间，并打印邀请。
房主占 1 席，因此这一步只适合一台成员设备加入；要扩到更多设备，显式改成
`host --tier business --seats N`，N 含房主且最大 200。**窗口保持打开。**

**③ 手工授权时的真实路径**

授权是**机级**的，默认位置：

```text
$DSH_HOME\agentdeck-super\.agentdeck\license\key.txt
```

`DSH_HOME` 未设置时，Windows 默认是 `$HOME\.dsh\agentdeck-super\.agentdeck\license\key.txt`。推荐用 `/deck` 页面或 `deck_license activate`，不要照抄旧文档的工作区路径。

**④ 手工起 relay（可选）**

```powershell
node .\tools\relay-server.mjs --port 8787 --host 0.0.0.0 --data .relay-data
```

看到 `http://<局域网IP>:8787` 后保持窗口。

**⑤ 手工建房间（可选）**

```powershell
node .\bin\nexi.mjs call deck_room '{"action":"create","name":"双机测试","relayUrl":"http://<甲的IP>:8787"}'
```

输出网页邀请和 `dsh://` 邀请。真机优先发网页形态那条。

### 4.4 电脑乙（客人）

```powershell
New-Item -ItemType Directory -Force -Path C:\nexi-B | Out-Null
Set-Location C:\nexi-B
tar -xzf <拷来的>\agentdeck-super-1.11.5.tgz
Set-Location .\package
```

推荐直接用配对工具：

```powershell
@'
<甲机发来的网页邀请链接>
'@ | Set-Content -LiteralPath .\invite.txt -Encoding ascii
node .\tools\nexi-pair.mjs guest --invite-file .\invite.txt --name "乙机-测试"
```

每台设备都用同一条邀请，名字必须不同；房主可执行
`node .\tools\nexi-pair.mjs members` 看完整席位名单。当前没有“按员工单独签发/撤销”
的生产控制面，邀请仍然是占席凭证。

手工 `deck_room` 时正确参数是 `inviteUrl`：

```powershell
node .\bin\nexi.mjs call deck_room '{"action":"join","inviteUrl":"<甲机发来的链接>","memberName":"乙机-测试"}'
```

**客人不需要授权码。** `deck_room` 没有 `send` / `pull`；后续用 `sync`。

### 4.5 真实任务交付验收

甲机：

```powershell
node .\tools\nexi-pair.mjs task add --title "乙机帮我看下日志" --acceptance "给出结论并回传"
node .\tools\nexi-pair.mjs sync
```

乙机：

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
node .\tools\nexi-pair.mjs task claim --id <任务号>
node .\tools\nexi-pair.mjs sync
```

甲机确认 `running`：

```powershell
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

乙机完成，甲机确认 `done`：

```powershell
# 乙机
node .\tools\nexi-pair.mjs task done --id <任务号> --output "已完成"
node .\tools\nexi-pair.mjs sync
# 甲机
node .\tools\nexi-pair.mjs sync
node .\tools\nexi-pair.mjs task list
```

### 4.6 验收清单

| # | 检查项 | 怎么验 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 两台都装好 | `node .\bin\nexi.mjs list` | 各打印 23 个工具 |
| 2 | 甲机授权生效 | `/deck` 或 `deck_license` | 显示协作版 |
| 3 | 建房间 | 甲机 `nexi-pair host` | 拿到 roomId + 邀请 |
| 4 | 进房间 | 乙机 `nexi-pair guest` | 双方同一个 roomId |
| 5 | 任务下发 | 甲 add，乙 sync + list | 乙看到任务 |
| 6 | 认领回传 | 乙 claim + sync，甲 sync | 甲看到 `running` |
| 7 | 完成回传 | 乙 done + sync，甲 sync | 甲看到 `done` + 产出 |
| 8 | 持久化 | 停 relay 重启 | 本地历史任务还在 |
| 9 | 跨机串门 | invite → accept → ask → receive | 便签加密且落成任务 |
| 10 | 断网降级 | 停 relay 后读本地板 | 不挂死、不崩 |

### 4.7 跨公网（可选）

relay 默认是 HTTP。跨公网必须上 HTTPS：

```powershell
node .\tools\relay-server.mjs --port 8787 --host 0.0.0.0 --data .relay-data --tls-cert <证书.pem> --tls-key <私钥.pem>
```

证书可以用 `node .\tools\make-cert.mjs` 自签（内网够用），或买正式证书。
2026-11-08 已用 Cloudflare Quick Tunnel 实测公网 HTTPS 的 MCP 四项检查，
证据见 `docs/evidence/public-1.11.2.txt`。公网 relay 配对的历史证据
`docs/evidence/public-pair-1.11.1.txt` 仍是同一台物理机的两个独立安装，
不能当成第二台物理机验收；真双物理机必须按第 4 节自己跑。

### 4.8 已有公网入口时的配对

如果你已经有能回源到本机的公网地址（反代 / frp / Tailscale Funnel / 内网穿透）：

```powershell
node .\tools\nexi-pair.mjs host --public-url https://你的域名
```

也可以自动启动临时隧道（需安装 cloudflared，或用 npx localtunnel 兜底）：

```powershell
node .\tools\nexi-pair.mjs host --tunnel cloudflared
node .\tools\nexi-pair.mjs host --public
```

命令必须先探测到公网 `/healthz` 返回 200，才会把邀请链接换成公网 origin 发给第二台设备。
本地 relay 仍然记录在 `state.json` 的 `localRelayUrl`；关房时会连隧道进程一起清理。

**注意**：本机已实测 `--public-url` 会先探活再建房；`cloudflared` 临时隧道也已在
2026-11-08 通过公网 `/healthz`、带 token 握手、`tools/list` 和 relay 配对任务闭环。
`cloudflared` 若不在 PATH，1.11.5 会回查 Program Files 与 WinGet Links。
Quick Tunnel 是临时域名，关掉进程即失效；长期服务用自己的域名/反代或托管 relay。

## 5. 桌宠 / 数字分身

### 5.1 看它长什么样

```bash
node bin/nexi.mjs call pet_skin "{\"action\":\"list\"}"
node bin/nexi.mjs call pet_skin "{\"action\":\"render\",\"id\":\"nio\",\"state\":\"working\",\"size\":128}"
```

五种状态：`idle`（发呆）/ `working`（搬砖）/ `meeting`（开会）/ `visiting`（串门）/ `sleeping`（睡了）。

### 5.2 它在学你什么

```bash
node bin/nexi.mjs call twin_brief
```

它记录：你几点开工、常用哪些工具、常做哪类活。
**同一动作重复 3 次**才会升成"习惯"，最多记 40 条。

边界：这是**统计出来的习惯**，不是真学习。档案里写的字不会被当命令执行。

### 5.3 人格包（让分身可自制）

放这里：`<工作区>\.agentdeck\pet\personas\<id>\persona.json`

```json
{
  "id": "my-style",
  "name": "我的风格",
  "tone": "直给结论，不铺垫",
  "style": "先看现状再动手",
  "principles": ["改完必须跑一次", "不确定就问"],
  "decisionBias": { "riskAppetite": "low", "askBeforeWrite": true }
}
```

内置两套种子（`steady-operator` / `sharp-reviewer`），可以照抄改。

### 5.4 技能包

放这里：`<工作区>\.agentdeck\pet\skills\<id>\skill.json`

```json
{
  "id": "my-skills",
  "name": "我的技能",
  "skills": [
    { "id": "sql-review", "name": "SQL 审查", "when": "有人提交 SQL", "how": "查索引/全表扫描/注入点", "role": "reviewer" }
  ]
}
```

### 5.5 串门（不需要服务器）

```bash
# 甲：生成邀请
node bin/nexi.mjs call pet_visit "{\"action\":\"invite\",\"scope\":\"work\",\"ttlHours\":2}"
# 输出 dsh://agentdeck/visit?t=xxxxx

# 乙：收下
node bin/nexi.mjs call pet_visit "{\"action\":\"accept\",\"token\":\"xxxxx\"}"

# 乙：造一张加密便签（box 用上一步返回的）
node bin/nexi.mjs call pet_visit "{\"action\":\"ask\",\"title\":\"帮我看下报表\",\"box\":\"<box>\"}"

# 甲：收下（把便签 JSON 贴进去）会落成一条任务
node bin/nexi.mjs call pet_visit "{\"action\":\"receive\",\"note\":<便签JSON>}"
```

### 5.6 增量同步（多设备日常用这个，不用每次全量）

原来的 `deck_sync` 是全量打包 —— 改一条记忆也要重新导一次大串。现在有增量：

```bash
# 设备甲：算出"上次之后的变化"，并把手上的进度推进
node bin/nexi.mjs call deck_sync "{\"action\":\"delta\"}"

# 设备乙：把甲给你的那批变化合进来
node bin/nexi.mjs call deck_sync "{\"action\":\"merge\",\"incoming\":[...]}"

# 两边都可以看同步进度（推到哪了 / 收到哪了）
node bin/nexi.mjs call deck_sync "{\"action\":\"delta\"}"
```

**冲突处理（重要，别以为是 bug）**：

| 类型 | 行为 |
| --- | --- |
| 流水 / 事件 / 知识 | 时间新的覆盖旧的（自动） |
| **人格 / 偏好 / 习惯** | **不自动覆盖** —— 列出来让你定 |

为什么不自动覆盖人格：两台设备都改过的话，自动选一个等于**悄悄改掉你的分身性格**。
所以它会列出来，你确认之后再用 `resolveConflict` 采纳。

**边界（写清楚）**：
- 增量同步只负责"算什么该传"，**怎么把数据送过去**仍由你决定（房间 / U 盘 / 手动贴）
- 没有自动发现机制：两台设备不会自己找到对方
- 同一字段两边同时改 → 按时间戳定胜负，不做字符级合并

### 5.7 同步进度在哪

游标文件：`<工作区>/.agentdeck/sync-cursor.json`

```json
{
  "pushCursor": 1794068000000,   // 已经推给对面到哪个时间点
  "peerCursor": 1794067000000,   // 已经从对面收到哪个时间点
  "lastSyncAt": "2026-11-08T...",
  "device": "dev_xxxx"           // 本机设备指纹
}
```

删掉这个文件 = 下次同步会当作"从零开始"（会重传一遍全量变化，不会丢数据）。

## 6. 分身执照

### 6.1 为什么要它

桌宠要"24 小时替你干活"，必须先回答：**它凭什么敢自己动手？**
执照就是那张授权状——由**你自己**签发给自己的分身。

### 6.2 看当前执照

```bash
node bin/nexi.mjs call twin_mandate "{\"action\":\"show\"}"
```

没签过会如实说"分身现在不会自主行动，所有事都要你点头"。

### 6.3 签一张（默认最小权限）

```bash
node bin/nexi.mjs call twin_mandate "{\"action\":\"issue\"}"
```

默认范围：只读工具 + 只写任务板；`shell`、`fs_write` 在禁止清单里。

### 6.4 自定义范围

```bash
node bin/nexi.mjs call twin_mandate "{\"action\":\"issue\",\"tools\":[\"fs_read\",\"fs_glob\",\"web_fetch\"],\"actions\":[\"board_add\"],\"deny\":[\"shell\"],\"perDay\":20,\"windows\":[\"09:00-22:00\"],\"ttlDays\":30}"
```

### 6.5 判定规则（写死，别猜）

```
1. deny 命中        -> 拒绝（用户明说禁止的，优先级最高）
2. 时间窗口外       -> 拒绝（到点就歇）
3. 预算超了         -> 要主人确认
4. 不在白名单       -> 要主人确认（回去问，不是直接拒）
5. 通过            -> 放行
```

### 6.6 预演一个动作

```bash
node bin/nexi.mjs call twin_mandate "{\"action\":\"check\",\"tool\":\"fs_write\"}"
```

### 6.7 吊销

```bash
node bin/nexi.mjs call twin_mandate "{\"action\":\"revoke\",\"id\":\"mand_xxxxx\"}"
```

**边界**：离线凭证没有吊销中心——本机不认了，但那张执照在别人机器上照样验得过。

### 6.8 主人手动覆盖

分身自主调用时带 `"autonomous": true` 就会过执照闸门。
主人手动加 `"confirm": true` 可以越过执照（主人的手比执照大），但**越不过 policy 的 deny**。

## 7. 发布前验收

### 7.1 一条命令跑完 18 项

```bash
npm test                             # 全量单测，Windows 下会显式枚举测试文件
npm pack --pack-destination .        # 先打包（两台电脑/可移植项需要它）
$env:NEXI_E2E_BASE='http://127.0.0.1:58399'   # 只有显式给地址才真跑外部宿主 e2e
node tools/verify-acceptance.mjs
```

**判定标准**：`0 项失败`。跳过的项要能解释清楚为什么跳过。`installed-host` 和 `m4`
会用临时 `DSH_HOME` 和临时 profile 真跑，不碰你自己的 `~/.dsh`；如果本机确实没有
`dsh`，验收报告会明确写「跳过」，不会伪装成通过。

本次 1.11.5 的真实基线是：全量 `1075 条 / 1060 通过 / 0 失败 / 15 跳过`（98 个测试文件），
验收 `18/18`，发布门禁 `15/15`。没有 `NEXI_E2E_BASE` 时，15 条外部宿主测试会洁净跳过，
不会自动探测固定 `58399` 端口。

**路径约定**：`node tools/verify-portable.mjs` 和 `node tools/verify-twomachines.mjs`
要在能找到 `agentdeck-super-1.11.5.tgz` 的包根目录执行；已经解包的 `package/` 子目录里
没有这个 tgz，直接跑会报 `ENOENT`，不是包坏了。

## 9. 赚钱：发码与收款

### 9.1 一次性准备

```bash
node tools/license-cli.mjs init
```

生成一对密钥。**私钥永不外传**（`~/.agentdeck-issuer/issuer-private.pem`）。

如果要自己卖码，推荐只在启动 relay / 宿主时把生成的公钥设为 `AGENTDECK_LICENSE_PUBKEY`。源码里的 `ISSUER_PUBLIC_SPKI_B64URL` 属于发行版发布配置，普通用户不要改；如果确实要自建发行方，改公钥后必须重新发码并逐台验证，旧码不会自动兼容。私钥要单独备份，不要覆盖已经签发的旧私钥。

### 9.2 卖一单（1 分钟）

```bash
# 客户付款后
node tools/license-cli.mjs issue --tier plus --to "客户名" --days 365 --seats 8
# 把打印出来的 ADSK1.… 发给客户

# 自检
node tools/license-cli.mjs verify ADSK1.xxxxx

# 看已发的码
node tools/license-cli.mjs orders
```

### 9.3 四档价格

| 档位 | 价格 | 席位 | 云房间 | 并行 |
| --- | --- | --- | --- | --- |
| 免费 | 0 元 | 3 | 0（本地房间 3） | 1 |
| 协作版 `plus` | 29/月 或 288/年 | 8 | 20 | 3 |
| 工作室版 `studio` | 99/月 或 999/年（含 3 席，加席 25/席·月） | 30 | 50 | 6 |
| 企业版 `business` | 30000 起/年 | 200 | 200 | 10 |

### 9.4 收费点在哪（重要）

- **不卖"本地功能解锁"**——本地 JS 拦不住改代码的人。
- 只卖**服务端才有的东西**：云房间配额、托管分身、模型额度。
- 付费点在**房主**：房主付费建房，客人凭链接进来免费。

### 9.5 托管 API（服务端配额）

relay 已经带上这些接口：

```
GET  /v1/plans               档位表（公开）
POST /v1/activate            授权码换令牌 { code, deviceId }
POST /v1/usage               用量 { tokens } 或查询
POST /v1/rooms/claim         建房配额（Bearer）
POST /v1/rooms/release       关房释放（Bearer）
```

自建 relay 的人一行就带上配额；托管方也是同一份代码跑公网。

### 9.6 自己搭 relay 卖给别人

```powershell
node tools/license-cli.mjs init                    # 生成你自己的密钥
$env:AGENTDECK_LICENSE_PUBKEY = '<你的公钥>'        # 让 relay 只认你的码
node tools/relay-server.mjs --port 8787 --host 0.0.0.0 --data .relay-data
```

## 10. 排障手册

### 10.1 装不上

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 解包报 `Failed to open archive` | 系统 `tar` 不支持中文路径 | 用 `node -e "import('./lib/untar.js').then(m=>m.extractTgz('<tgz>','.'))"` |
| `node --version` 低于 22.12 | 版本不够 | 升级 Node |
| `npm pack` 报中文路径错 | 系统代码页 | 换英文路径 |

### 10.2 连不上

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 乙机连不上 relay | 甲机防火墙 | 放行 8787 端口 |
| 同上 | 用了 `127.0.0.1` | 改成局域网 IP |
| 同上 | 不在同一网段 | 确认两台在同一局域网 |

### 10.3 授权问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 建房间返回 402 | 免费版没有云房间 | 用协作版授权码 |
| 授权码验不过 | 公钥不匹配 | relay 的 `AGENTDECK_LICENSE_PUBKEY` 要和发码用的私钥配对 |
| `license-cli init` 报"已存在" | 已经生成过 | 别覆盖（覆盖后老客户全废），用 `--out` 指定别的目录 |

### 10.4 串门问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 验签失败 | 两条链接不是同一次生成 | 重新生成一对 |
| 便签解不开 | 对面没给 `box` | 邀请返回值里要有 `box` 字段 |
| `cannot_decrypt` | 用错了 box | 用**对方**的 box，不是自己的 |

### 10.5 测试偶发失败

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 全量跑偶发红，单独跑绿 | 环境残留（端口/临时目录） | 已加隔离性测试；仍出现就重跑一次并记下来 |

## 11. 已知边界

**这些是我们没做到的，写清楚不装。**

| 项 | 边界 |
| --- | --- |
| 真钱进账 | 代码路径全通（本地真 HTTP 网关 53/53、Stripe 形状适配器 26/26），但本机没有真实商户号，**真钱这条没走通** |
| 跨机隔离 | 房间成员**默认互相信任**（同团队场景），不是多租户隔离 |
| 邀请即凭证 | 拿到邀请链接的人就能进房间（这是设计） |
| 身份证明 | 通行证/执照证明"没被改过"，**不证明"屏幕前是谁"** |
| 在线吊销 | 离线凭证没有吊销中心，`revoke` 只标本地账本 |
| 分身自主 | 受执照限制；默认最小权限，不是"完全自主" |
| 桌宠窗口 | 浏览器无边框小窗，做不到逐像素透明与鼠标穿透 |
| 会议质量 | 取决于宿主模型；纪要由模型生成，原文发言原样保留 |
| 跨操作系统 | Windows->Linux 未测 |
| 断电恢复 | 进程级故障验过；断电/磁盘坏道未覆盖 |
| 托管分身 | 设计完成，**服务端实例还没上线** |
