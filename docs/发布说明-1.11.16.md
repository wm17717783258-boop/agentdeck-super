# 1.11.16 —— 一个包，三个系统

**一句话**：插件不分系统。以前"分"，是因为四个宿主的配置路径只写了 Windows 那一套，
在 macOS 上会算成 `~/AppData/Roaming/...` —— 路径不存在 → 探测说"宿主未安装" →
用户看到的现象是"这插件不支持 Mac"。这版把表按系统拆正，并加了 12 条矩阵测试锁住。

## 改了什么

### 1) 宿主配置路径：从"Windows 写法"改成"按系统查表"

| 宿主 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| Claude Desktop | `%APPDATA%\Claude\` | `~/Library/Application Support/Claude/` | `~/.config/Claude/` |
| VS Code | `%APPDATA%\Code\User\` | `~/Library/Application Support/Code/User/` | `~/.config/Code/User/` |
| Cline | 同上 + `globalStorage/...` | 同上 + `globalStorage/...` | 同上 + `globalStorage/...` |
| Zed | `%APPDATA%\Zed\settings.json` | `~/.config/zed/settings.json` | `~/.config/zed/settings.json` |

- 新增 `lib/connect/platform.js`：把"哪个系统"收成一个可注入的上下文，三张表放在一处。
  **不是两套代码**，同一份代码按表查。
- 路径拼接按目标系统选 `path.win32` / `path.posix` —— 在 Windows 上算 macOS 路径时
  不会吐出反斜杠，否则测试就成了自欺。
- `XDG_CONFIG_HOME` / `APPDATA` / `COPILOT_HOME` 有值时一律优先，没值时给绝对兜底，
  不会拼出 `npm` 这种相对路径。
- VS Code 家族顺带补了 `Code - Insiders` / `VSCodium` 两个候选目录。

### 2) 本机 CLI 探测：macOS / Linux 也补上落点

`lib/engine/cli.js` 的额外候选目录原来只有 Windows 那几处。macOS 从 Dock 启动的宿主
拿不到 shell 的 PATH，连 `/opt/homebrew/bin` 都可能不在。现在补：
`/usr/local/bin`、`/opt/homebrew/bin`、`/opt/local/bin`、`~/.local/bin`、
`~/.npm-global/bin`、`~/.bun/bin`，以及 DeepSeek Harness.app 内的 CLI。

### 3) 新命令 `nexi where`

```
npx -y agentdeck-super@latest where
```

一屏打出 13 个宿主 × 三个系统的落点，当前系统那列标 `←`；`--json` 给机器读。
这是给"你到底支不支持 Mac"这个问题一个当场能看见的答案，而不是让人相信一句话。

## 测试

- 新增 `tests/platform-matrix.test.mjs`：**12 条**。
  - 三系统逐字核对 4 个曾写死 Windows 的宿主路径；
  - 全局禁令：darwin / linux 的任何候选路径不许出现 `AppData` 或反斜杠；
  - `XDG_CONFIG_HOME` / `APPDATA` 缺失时的兜底；
  - `detectHosts(ctx)` 三系统都能跑、13 个宿主不少；
  - `nexi where` 文本与 `--json` 两条出口。
- **突变验证**：把 Claude Desktop 改回 `envPath('APPDATA', …)` 那版，测试红 3 条；
  还原后全绿。不是摆着好看的测试。
- 全量：**1197 条 / 1182 通过 / 0 失败 / 15 跳过**（114 个文件）。

## 边界（不改口）

- 手上没有第二台 Mac / Linux 真机。矩阵测试锁的是**路径算得对**，
  锁不住"在真 Mac 上点开 Claude Desktop 看见 23 个工具"。
- 宿主的配置文件格式本身仍按官方文档形状写，没有在真 Mac 上验过写入与回滚。
- npm 上的 1.11.15 仍是上一版；这版没有自动发布，等你确认后再 `release.mjs --publish`。
