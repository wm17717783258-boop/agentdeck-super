# 任意设备：一条命令安装、反复更新、再测试

版本：`1.11.5`

## 先说结论

**能做的：**

- 任意一台有 Node.js 22.12+ 的电脑，执行同一条安装命令；
- 自动探测 Claude Desktop、Claude Code、Cursor、Windsurf、Codex、Cline / VS Code、Continue、Gemini CLI；
- 只把 **稳定启动器** 写进宿主配置；
- 改代码、重新打包后，一条更新命令切换到新版本；
- 失败不切版本，旧版本保留，可回滚；
- 所有设备共用同一个安装包和同一个工具入口。

**不能做的：**

- 不能承诺“所有主流 Agent 的同一个搜索框里都能搜到”。它们没有统一插件市场：
  - DSH 市场只给 DSH；
  - npm 是包仓库，不是每个 Agent 的搜索界面；
  - MCP Registry 只对支持 Registry 的客户端可见；
  - Claude Desktop / Codex / Cursor 等宿主各自有 MCP 配置方式。

所以真正的产品口径是：
> **一次发布，所有宿主用同一个安装入口；不是所有宿主共享同一个搜索市场。**

## 1. 上架后的最短路径

前提：`agentdeck-super` 已发布到 npm，且本机有 Node.js 22.12+。

```powershell
npx -y agentdeck-super@latest --all
```

这条命令做四件事：

1. 从 npm 取最新版；
2. 安装到固定目录：Windows 默认 `%LOCALAPPDATA%\Nexi`；
3. 写稳定启动器：`%LOCALAPPDATA%\Nexi\bin\nexi.mjs`；
4. 自动写本机已安装 Agent 的 MCP 配置。

装完验证：

```powershell
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" doctor
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" status
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" pair help
```

让宿主自己确认：

```powershell
claude mcp list
codex mcp list
gemini mcp list
```

装完直接做双机配对时，不要再去 `versions\<版本>\tools` 里找脚本；稳定入口就是：

```powershell
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" pair host
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" pair guest --invite-file invite.txt --name "张三-设计部"
```

## 2. 还没上架 / 离线交付

在交付包目录执行：

```powershell
Get-FileHash .\agentdeck-super-1.11.5.tgz -Algorithm SHA256
node install.mjs --bundle .\agentdeck-super-1.11.5.tgz
```

或者先从 tgz 解包，再在包目录执行：

```powershell
tar -xzf .\agentdeck-super-1.11.5.tgz
cd package
node install.mjs
```

`--bundle` 也接受 URL：

```powershell
node install.mjs --bundle https://example.com/agentdeck-super-1.11.5.tgz --sha256 <64位哈希>
```

没有给 `--sha256` 时，安装器会尝试读取 tgz 同目录的 `SHA256SUMS.txt`；两边都没有就照装，但会把实际 SHA256 打在结果里，不能把“没校验”说成“已校验”。

## 3. 改完代码后怎么再测

### 本机开发：直接让宿主跑源码

```powershell
node install.mjs --dev codex
```

这条是显式开发模式，宿主配置会指向源码目录。只适合本机调试，不要拿它做正式安装。

### 模拟用户安装：每次重新打 tgz

```powershell
npm pack --pack-destination .
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" update --bundle .\agentdeck-super-1.11.5.tgz
```

如果只是改本机源码、还没准备发布，直接跑：

```powershell
node install.mjs --no-hosts
```

它会把当前源码重新装进固定目录并切 `current.json`，不会改宿主配置；重启宿主后就是新代码。

更新流程是：

1. 解到 staging；
2. 检查 `package.json`、`bin/nexi.mjs`、`lib/hub.js`、MCP server；
3. 通过后原子切换 `current.json`；
4. 宿主配置仍然指向同一个稳定启动器；
5. 失败时当前版本不变。

回滚：

```powershell
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" rollback
```

## 4. 多台设备怎么测

每台设备只需要：

```powershell
npx -y agentdeck-super@latest --all
node "$env:LOCALAPPDATA\Nexi\bin\nexi.mjs" doctor
```

然后按项目里的跨机测试方案建 relay / 房间 / 邀请。**同一台设备上的两个进程不能冒充两台物理机**；每台设备是独立安装、独立数据目录、独立身份。

建议的席位验收顺序：

1. 设备 A 安装并建房间；
2. 设备 B 安装、凭邀请进房；
3. 两端各派一条任务，确认 claim / done 双向同步；
4. 设备 B 断网，确认本地工具仍可用；
5. 设备 B 重新联网，确认任务恢复；
6. 设备 A 更新到新 tgz，设备 B 仍走旧版，确认协议兼容；
7. 设备 B 也更新，确认宿主配置没有改路径；
8. 回滚设备 B，确认仍能进房。

## 5. 上架三条真实通道

### npm

```powershell
npm login
node tools\go-live.mjs
```

当前本机没有 npm 登录态，也没 `NPM_TOKEN`；npm 查询 `agentdeck-super` 仍是 404。没有账号不能伪造“已上架”。

### MCP Registry

```powershell
npm publish --access public
node tools\publish-registry.mjs --login
node tools\publish-registry.mjs --publish
```

需要 npm 包已存在，并需要 GitHub 设备码授权。

### GitHub Release / DSH 市场

GitHub Release 提供 tgz 下载入口；DSH 市场走 `dsh plugin add agentdeck-super`。它们是不同入口，不是“所有 Agent 都能搜到”的同一个市场。

## 6. 安装器真实验收命令

```powershell
node --test --test-concurrency=1 tests\installer.test.mjs
node install.mjs --dry-run --no-hosts
node install.mjs --home "$env:TEMP\nexi-clean-test" --no-hosts
node "$env:TEMP\nexi-clean-test\bin\nexi.mjs" status
```

固定目录测试必须验证：

- `current.json` 写了；
- `bin/nexi.mjs` 能起 Hub；
- 宿主配置的 `args[0]` 是稳定启动器，不是 `versions\...`；
- 换版本后这一行没变；
- 坏包不切版本；
- `rollback` 能恢复上一版。
