# Nexi 灵犀 1.11.3 发布说明

发布日期：2026-11-09

## 本次改动

### 1. 真机配对支持显式测试席位

`nexi-pair host` 新增：

```powershell
node tools/nexi-pair.mjs host --tier business --seats 10
```

- 默认仍是协作版 8 席，旧命令不变；
- `--tier` 可选 `free / plus / studio / business`；
- `--seats` 不能超过档位上限；
- 测试授权仍是 Ed25519 真签名、只在本进程临时生成，不是生产授权；
- 输出会明确写出总席位和可加入的客人设备数。

### 2. relay 按授权实际席位数放行

之前房间只按档位 `maxSeats` 放行：企业版哪怕只买 10 席，也会按 200 席开门。
现在改为：

```text
实际房间席位 = min(claims.seats, 档位 maxSeats)
```

并有回归测试验证：企业版 12 席时，主机 + 11 台客人可进，第 13 席返回 `room_full`。

### 3. 双机自检优先真实网卡

`verify-twomachines` 不再先抓 `198.18.0.1` 这类 Meta/VPN 虚拟网卡，改为：

- 优先真实 WiFi / 网线地址；
- 虚拟网卡只作本机回归，并在输出中明确标注“不代表第二台物理机可达”；
- 与 `nexi-pair` 的地址选择规则一致。

### 4. 新增极简测试文档

新增 `docs/多设备席位测试-极简版.md`，包含：

- 同一 tgz 分发；
- 房主开 2/3/10/50/200 席；
- 成员设备一行加入；
- 五个物理验收动作；
- GitHub/npm/MCP Registry 的实际差距；
- 发现问题后的重新打包闭环。

## 验证结果

- 全量测试：96 个测试文件，1068 项，1053 通过，0 失败，15 跳过；
- 定向席位测试：企业版 12 席精确放行；
- 配对全链路：host → guest → check 通过；
- 双机本机模拟：28/28 通过，使用真实 WLAN 地址 `192.168.1.10`；
- 清洁解包：463 个文件，安全扫描 0 高危/中危/低危。

## 仍未完成

- 没有在两台用户物理电脑上实测；上面的双机测试是同一台机器上的两个独立身份；
- 没有 npm 发布；
- 没有 MCP Registry 收录；
- 没有“无限席位”；
- 没有持久 relay / 高可用 / 按员工签发和回收席位；
- GitHub 上仍只有旧的 `v1.10.0` Release。

“无限席位”不是把 `maxSeats` 改成 `Infinity` 就完事。它需要项目级席位控制面、
管理员签发/回收、审计和持久 relay；当前 1.11.3 只做到最多 200 席的测试与协作。
