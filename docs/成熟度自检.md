# 成熟度自检（1.11.20 · 十轮）

对着用户那句话逐条查：**不分电脑系统、不分 Agent、不分网络、不分电脑设备**，然后查"成熟产品"该有的东西还缺什么。

这一版把自检做成**十轮**，每轮一个攻击面，每轮都要"改回实现能让测试变红"。每条都给**能当场复现的证据**，不给形容词。

## 十轮一览

| 轮 | 攻击面 | 这轮的关键结论 |
| --- | --- | --- |
| R1 | 平台路径 | 16 家宿主的落点写成**逐字契约**，改路径表必须同步改期望值 |
| R2 | 任意 Agent | 装得进去必须卸得出来；未知 shape 退出码 2 并列出全部可选 |
| R3 | 离线全链路 | 装/卸/体检/日志/坏代理逐条跑通，唯一要网的"更新自己"快速失败并给 `--bundle` |
| R4 | 文件编码 | BOM 保留、UTF-16 说人话、CRLF 不混行、缩进风格原样还回 |
| R5 | 任意设备 | 中文空格 emoji 长路径、只读盘、无 HOME、换盘、混用分隔符 |
| R6 | 守卫测试 | 平台分支白名单（10 文件，每个写明理由），白名单外出现即红、白名单腐烂也红 |

## 四、R7–R10 补掉的东西

### R7 故障注入：不正常时不许把事情弄得更糟

| 场景 | 以前 | 现在 | 验收 |
| --- | --- | --- | --- |
| 半截哨兵（上次写到一半被 kill） | 追加第二个块，文件更乱且以后删不掉 | 拒绝写入 → `reason:torn-sentinel` → 给 `nexi repair` 出口 | 只有 START / 只有 END 两个方向各一条 |
| 备份本身是半截 JSON | 回滚**成功**，把好配置覆盖成坏内容 | `backup-corrupt`，当前配置一字节不动 | 实测 `ok=false` 且"当前配置还在=true" |
| 只读文件 | CLI 抛 `EPERM` 堆栈退出并残留 `.tmp` | `permission-denied` + hint，temp 自清 | 断言无 `.nexi.tmp` 残留 |
| `state.json` 被截断 | 任务板永久空，用户不知道发生了什么 | 坏文件留证物 `state.json.corrupt-<时间>`（只留 3 份）+ 下次写入自愈重建 | 4 条测试，含"空文件不算损坏" |
| 陈旧 `.nexi.tmp` | 在用户目录里越堆越多 | 写盘前清 >1 h 的残渣，正在写的不动 | 造一份 2 小时前的残渣验证 |

### R8 安全攻击面

| 面 | 发现 | 处理 |
| --- | --- | --- |
| **命令注入** | `spawnSync(bin, args, {shell:true})` 在 Windows 上把参数拼成一整行交 cmd.exe：路径有空格就切断，名字里有 `&` `|` `>` 就能挂第二条命令 | 新建 `lib/connect/exec.js`：POSIX/`.exe` 直接 exec；`.cmd` 垫片自己逐参数加引号 + 外层 `/s` 引号；含 `& ｜ < > ^ %` 的参数**直接拒绝**并退回写配置文件 |
| **路径遍历** | `nexi host rm ../../x` 会删掉注册表目录外的 `x.json` | `removeCustomHost` 按 `ID_RE` 校验 id |
| **配置注入** | 宿主名/命令里塞换行、引号、`}` | YAML 用 JSON 双引号标量、TOML 用 JSON 字符串、JSON 交给 `JSON.stringify`；三条注入测试撑不破结构 |
| **日志泄密** | 只按 key 名过滤（`token`/`secret`），值里的凭据全裸奔 | 新增 `redactText`：URL 查询串凭据 / Bearer / `sk-` / JWT / ≥32 位十六进制，按**形状**洗 |
| **越界删除** | — | `unsafeReason` 逐条验：家目录、盘根、家目录上级、名字不含 nexi 全部拒绝 |
| **锁文件权限** | 0644，同机其他用户可读 | `openSync(...,'wx',0o600)` |

### R9 产品面一致性

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| `nexi instal codex`（手滑） | 打一页帮助、**退出 0** —— CI 以为装成功了 | 退出码 2 + 编辑距离猜出 `nexi install`；帮助照打 |
| `pet` / `config` / `relay` / `help` 实现了但没写进帮助 | 等于没有这个功能 | 补齐，并加测试**从源码命令表解析**后逐个核对帮助 |
| `nexi jobs --json` 无视开关，打人话 | 管道喂给 `jq` 直接炸 | `--json` 时输出 `{ok, action, output}` |
| `nexi logs --json` 没日志时零输出 | 脚本分不清"没日志"还是"命令坏了" | 空结果也吐一行汇总 |
| `nexi uninstall no-such-host` | 只说"不认识"，不说有哪些 | 补 `known` 列表 + hint（`host list` / `install custom` 两条出路） |
| 幂等 | — | CLI 端到端两条：`install custom` 两次第二次 `changed:false` 且字节不变；`config --all` 两次输出全等 |
| **「依据」列没人核** | 会原样进公开文档，虚标比不标更糟 | 新增 `tests/evidence-honesty.test.mjs` 7 条：三档取值域、`--md` 与 `--json` 同口径、清单文档与代码不脱节，以及**标了「本机实装」就必须在磁盘上查得到 nexi 痕迹**（备份文件或配置里的条目），查不到即红 |

最后一条值得单独说：起初这张表的 30 家**全部**是默认的「文档核对」—— 连真装过的 6 家也这么显示。
对外看是"一家都没验过"，和 `docs/接入的Agent清单.md` 里"6 家真装过"自相矛盾。
查下来是元数据漏填：4 家配置目录里躺着 21 / 21 / 21 / 13 份 nexi 备份，另 2 家走 CLI 写入
所以没有备份、但配置文件里的 `nexi` 条目还在。**凭磁盘上的痕迹补标，不凭记忆。**

补完之后这个数字从"0 家实装"变成 `本机实装 6 / 文档核对 22 / 社区约定 2`，
而且现在有测试盯着它 —— 谁想把某家往上标，得先让磁盘上有证据（测试会红）。
验证过这条测试真的会红：用一个临时 `USERPROFILE` 造出"配置在、但干净没痕迹"的场景，
它准确点名了 `claude-desktop`，不是永远绿的摆设。

### R10 性能与规模

| 指标 | 之前 | 现在 | 怎么做到的 |
| --- | --- | --- | --- |
| `detectHosts` 单次 | 44 ms | **2.5 ms** | `findOnPath` 结果按 `PATH` 缓存（一次探测 = 1 万多次 stat，绝大多数是白跑） |
| `nexi config --all` 端到端 | 1.79 s | **0.75 s** | 上面那条 + 探测从循环里提到循环外（原来 30 个宿主各探一遍全盘） |
| 30 家纯文件安装 | — | **0.85 s** | 备份/锁/原子写都是毫秒级，瓶颈只在探测 |
| 2.4 MB 配置文件装 / 卸 | — | 0.4 s / 0.32 s | 只重排自己那一段，整份 `JSON.parse`/`stringify` 一次 |
| 连装 150 次内存增长 | — | **0.0 MB** | 无全局累积 |
| CLI 冷启动 | — | 0.18 s | — |

阈值写成"比实测慢 3–10 倍才算失败"的护栏，不是跑分：写死"必须 12 ms"，换台慢机器就红，最后没人信它。

### 收尾：发布前体检又撞到三件"看起来没事"的事

十轮跑完、测试全绿之后去做发布体检，又翻出三件 —— 它们都不是功能 bug，
但每一件都会直接砸在用户脸上。

| 事 | 表面现象 | 真相 |
| --- | --- | --- |
| **冒烟自检长期 4/5** | `npm run smoke` 有一条永远失败 | 跨机协同那条断言查的是**客人自己建的组**，而进房后小组会被换成房主那个（`lib/room.js` 里 `teamId` 被改写）。协作必须共用一个组，所以产品是对的，**断言盯错了对象**，从上线起就一直红着 |
| **没人守着那个脚本** | 上面那条烂了很久没人发现 | `tests/e2e-local.mjs` 不在 `tests/*.test.mjs` 里，`npm test` 从来不跑它。**最像"验收"的那个脚本，反而没有测试盯着** —— 已补一条守卫：`npm run smoke` 必须 5/5 |
| **发布包里塞了 123 个测试文件** | `npm pack` 331 个文件 / 1368 KiB | `files` 里写着 `"tests"`。收到 **209 个文件 / 1005 KiB（−27%）**，只留 `tests/e2e-local.mjs` 和它要的 `fake-agent`（否则装完 `npm run smoke` 直接报模块找不到 —— 这是打包后真跑出来的，不是推的） |

还顺手修了 `tools/publish-npm.mjs` 的一个哑巴 bug：它解析用例数只认 `ℹ pass`，
而裸 `node --test` 出的是 TAP 的 `# pass` —— 于是每次发布体检都显示 `pass ?`。
现在两种格式都认，**解析不到就直接报错拦住发布**，不许再显示 `?`。

这三件事有个共同点：**它们都在测试覆盖之外**。
十轮自检盯的是代码行为，而"用户拿到包之后第一步会做什么"没人盯 ——
`npm run smoke` 就是他做的第一件事。这个盲区比任何一个函数 bug 都值得记一笔。

## 五、这十轮里最值钱的三件事

1. **R7 在真机上撞到的两个 bug，都不是测试能想出来的**：
   - `codex mcp add nexi` 会把 `~/.codex/config.toml` 整份重新序列化，**把我们的哨兵注释全丢掉**，只剩一个裸 `[mcp_servers.nexi]`。而 `uninstall` 只认哨兵 → **装得进去、卸不出来**，还返回 `changed:false`（静默）。现在按表名精确删除，别的 `[mcp_servers.xxx]` 一行不碰。
   - 同一台机器上 `nexi config --all` 整条命令失败，只因为 codex 的历史文件里有半截哨兵。**预览不该被目标文件的历史状态拖死** —— 现在 `config` 仍然给出正确片段，只是标 `needsRepair:true` 并告诉你跑 `nexi repair`。
2. **R8 的命令注入不是理论风险**：npm 全局装的 CLI 垫片里写的是 `%*`，`%*` 会**原样展开**，父进程加的引号在垫片里已经被剥掉 —— 所以"加引号就行"是错的，唯一稳的做法是不放行那些字符。
3. **R10 的性能问题出在"只读操作被调太多次"**：44 ms 单次探测没人会觉得慢，但 `config --all` 乘 30 就变成秒级卡顿。缓存一行代码，用户感知从"肉"变"跟手"。

## 六、还差的（诚实版）

1. **P0 · 真机矩阵**：30 家里**本机实装 6 家、文档核对 22 家、社区约定 2 家**，剩下 24 家要拿 2–3 台真机（Mac / Linux / 另一台 Windows）跑一遍才能降下来。**这是当前最大的未知，任何代码改动都替代不了。**

   这个数字不是拍脑袋写的，是查出来的：`nexi host list` 的「依据」列就是它，凭据是本机配置目录里查得到痕迹（nexi 备份文件，或配置里还在的 nexi 条目）。谁想自己核，跑：

   ```
   nexi host list                     # 看「依据」列
   nexi host list --md                # 同一份数据，Markdown 表格
   ```

   也要说清 6 家「本机实装」**到底验到哪一步**：跑过 install、看过写进去的字节、跑过 uninstall 且卸干净。**没有重启宿主 GUI 看工具列表** —— 那一步只有人坐在机器前能做。所以「本机实装」不等于「这个 Agent 一定能用」。
2. **图形界面**：全命令行，桌宠是唯一 GUI 形态。要不要做、做成什么样，是产品决定，不是补丁。
3. **多语言**：中文为主，英文只有 README 片段。
4. **YAML 覆盖面**：只处理块状 map / 块状 seq / 流式数组；锚点、别名、多文档 `---` 遇到会拒绝改写（不猜）。
5. **JSONC 只读不写**：读得懂注释与尾逗号，但要改就拒绝整份重写（`reason:jsonc-preserve`）并给 `nexi snippet` 手工方案 —— 毁注释比不装更糟。
6. **并发锁只保单机**：两台机器同时写网络盘上的同一个配置，不在保护范围（也没打算做分布式锁）。
7. **宿主升级改格式**：宿主大版本改配置格式时，只能靠用户报错或 `doctor` 发现条目失效，做不到提前预知。

## 七、结论

- 四个"不分"都有**可复现的证据**，不是口头承诺。
- 成熟度表里除图形界面与多语言外，全部 ✅。
- 全量 **1409 条 / 1392 通过 / 0 失败 / 17 跳过**（17 条是平台专属用例，在非对应系统上跳过并写明理由）。
- 最大的诚实点没变：**30 家里只有 6 家在本机真装过**，其余 24 家是文档级适配。这一条不改口。
