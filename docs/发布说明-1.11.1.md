## 这版修了什么

1. **公网隧道找不到 cloudflared**
   winget 装完不刷新当前进程 PATH，导致 `--tunnel cloudflared` 明明装了却报
   `The argument 'file' cannot be empty`。现在 PATH 找不到时会补查
   `%ProgramFiles(x86)%\cloudflared`、`%ProgramFiles%\cloudflared` 和 WinGet Links。

2. **显式指定不可用 provider 时仍尝试 spawn**
   `--tunnel cloudflared` 在 cloudflared 不存在时不再用空命令启动，直接给出
   「本机没有可用的隧道 provider」和安装提示。

3. **证据文件版本写死**
   `verify-billing-live.mjs`、`verify-everything.mjs` 之前固定写 `1.10.0`，
   升版本后发布门禁会误报「缺证据」。现在从 `package.json` 读版本。

4. **新增 `tools/verify-public.mjs`**
   一条命令起本地 MCP + 公网隧道，从公网侧验 `/healthz`、无 token 401、
   Bearer 握手、`tools/list`。全过才打印 `PASS`，证据写到
   `docs/evidence/public-<版本>.txt`。

5. **发布文档口径清理**
   去掉“公网 HTTPS 尚未验收”等与 1.11.1 证据冲突的旧描述；
   明确公网验收仍是同机双安装，真双物理机、跨操作系统、真实扣款和云托管没有冒充通过。

6. **修掉可移植性验收的假绿灯**
   `tools/verify-portable.mjs` 之前收到 `initialize` 就结束并返回 0，
   根本没等 `tools/list`，属于“只看服务起来、没验工具面”。现在必须两项都回话，
   且工具数与本机 `HUB_TOOL_ORDER` 一致，才打印 `2/2 通过`。

## 公网验收实测

2026-11-08 用 Cloudflare Quick Tunnel 真跑：

- `nexi serve --tunnel cloudflared` 分配公网 HTTPS 域名并通过 `/healthz`。
- 从独立进程访问公网端点：`healthz 200`；无 token `initialize` 返回 `401`；
  带 `Bearer` 返回 `200`；`tools/list` 返回 23 个工具。
- `nexi-pair host --tunnel cloudflared` 建立公网 relay；乙机（独立项目副本 +
  独立状态目录）用公网邀请链接进房，成员 2 人。
- 甲机发任务 → 乙机 `sync` 拉到、`claim`、`done` → 甲机 `sync` 看到 `done`。

## 边界（不许当已验收）

- 公网配对仍是**同一台物理机的两个独立安装**，不是两台物理电脑。
- Quick Tunnel 是临时域名，进程关闭即失效；长期服务要自己的域名/反代或托管 relay。
- 跨操作系统（Windows → Linux/macOS）没测。本机没有 WSL/Docker。
- 8 个宿主里本机只装了 Codex，其余 7 个是「未安装且拒绝伪造配置」。
- 支付验的是代码路径，**没有真实商户号，没验真扣款**。
- 在线吊销、多租户隔离、在线身份绑定仍未上线。
