对账（渠道流水 ↔ 本机订单 ↔ 账本）1.10.0 取证
================================================

结论：真实收款的最后一块（**账能不能对上**）做出来了，而且**不需要商户号就能验**。

一、为什么这块必须有
  1.10.0 之前，市场侧已经能做到：下单 → 渠道回执 → 发放 → 幂等 → 退款。
  但"能付"不等于"账对得上"。渠道那边有一条流水，我们这边有一张订单 + 一笔账本，
  三者的 订单号/金额/状态/渠道流水号 必须能逐笔勾对——
  少一笔、多一笔、金额对不上，都要**当场说出来**，而不是等月底发现钱不对。

二、这一层做什么（lib/market/reconcile.js）
  输入：一份渠道对账单（数组，一行一笔）+ 本机订单 + 分账账本
  输出：逐笔勾对结果 + 差异明细（**只报差异，绝不自动改账**）

  差异六类，每类都写清"谁的锅"，方便分派：
    · missing_local    渠道有、我们没记   → 可能漏单
    · missing_remote   我们有、渠道没有   → 可能没真扣款（最该警惕）
    · amount_mismatch  订单号对得上、金额对不上
    · state_mismatch   金额对得上、状态对不上（比如渠道说退款、本机还是已付）
    · ref_mismatch     渠道流水号对不上   → 可能被改过
    · duplicate_remote 渠道同一张订单出现两次 → 可能重复扣款

  容错（不猜、不静默跳过）：
    · 渠道字段名认常见写法：orderId / order_id / out_trade_no / metadata.orderId；
      amount / total / totalAmount / total_amount / amount_cents；
      ref / transactionId / tradeNo；state / status
    · 渠道按"元"给金额时传 unit:"yuan"，内部统一归一到"分"再比
    · 缺订单号的脏行**如实报出来**，不静默跳过
    · 对账单不是数组 → 明确拒绝；没传/null → 按空对账单处理（"还没拉到流水"是合法状态）

三、怎么证明（不需要商户号）
  单元/集成：tests/reconcile.test.mjs —— **15 条全过**
    全对上零差异 / missing_local / missing_remote / amount_mismatch /
    unit:yuan 归一 / state_mismatch（含退款方向）/ 退款对齐不算差异 /
    ref_mismatch / duplicate_remote / 脏输入不崩 / 缺单号如实报 /
    字段别名 / 报告逐条列出 / **对账是纯读的（跑完订单文件一个字节没变）**

  真机工具层（deck_market action=reconcile）：
    · 对得上 → 「勾对成功 1 笔，无差异」
    · 金额不符 + 渠道多一笔 → 两条差异都列出来，各自指明类别
    · 对账单 JSON 写坏 → 「对账单 JSON 解析失败：…」不崩
    · unit=yuan（渠道按元给 18）→ 正确对到本机 1800 分

  deck_market 的动作表：catalog / health / buy / orders / refund / **reconcile**
  只读模式放行 reconcile（已证明是纯读，不给写权限的人也能对账）

四、边界（照写，不美化）
  ✗ 这一层**不自动改账**：只报差异。改账是最危险的动作，必须由人决定补单还是退款。
  ✗ 不做"我们主动去渠道拉流水"：拉流水要商户号。配齐之后同一套勾对逻辑直接吃真流水，
    但"拉"这一步现在没验过。
  ✗ 不校验渠道对账单本身的签名（那是各渠道 webhook 验签的活，见 lib/billing/sign.js）。
  ✗ **发票 / 税费仍然没做**。门槛 ⑥ 依旧开着。

五、门槛 ⑥ 的现状（更新）
  之前写：❌ 未通过（本机没有商户号）
  现在细分为：
    ✅ 支付链路本身真跑通（真 HTTP → 回执 → 发放 → 幂等 → 退款冲正）
    ✅ Webhook 幂等与验签（lib/billing/idempotency.js、sign.js；自动化侧的回调也验过）
    ✅ **对账**（1.10.0 新增，本文件）—— 不需要商户号就能验，已验
    ❌ 真实商户号：没有。未配时一律回「环境未配」，订单停在 created，不编流水号。
    ❌ 发票 / 税费：没做。
  所以对外仍然**不许**说「真实支付」——只能说「链路通、只差一个商户号」。
