1.0 上线硬门槛逐条对账（agentdeck-super 1.10.0）
=================================================

蓝图《Nexi灵犀-最终版插件产品方案》第 401-411 行列了 9 条硬门槛，并写明：
「任何一项未通过，就不能用"全兼容""顶级桌宠"或"真实支付"对外描述。」

下面逐条对账。**开着的就写开着**，不做含糊表述。

① 8 个宿主真实安装 / 调用 / 卸载          —— 🟡 部分通过（3/8 真认证）
   证据：docs/evidence/hosts-1.10.0.txt
   ✅ Claude Code       装→宿主自报(nexi)→卸→配置逐字节还原
   ✅ Codex             同上
   ✅ Gemini CLI        同上（1.10.0 新认证）
   🟡 Claude Desktop    只验到配置层 → 标「实验性」。**原因是平台事实**：本机实测
                        claude-desktop.exe --version 能出 4.4212.0，但 --help / mcp list
                        会把桌面 GUI 拉起来并挂住，它不是 CLI。所以只能验
                        「配置写对 + 装卸一致（逐字节还原）」，验不了「宿主自己认不认」。
   ⚪ Cursor / Windsurf / Cline / Continue   本机未安装 —— **拒绝伪造配置**
   逻辑：没装的宿主就算不出来。要凑满 8 个只能去装它们，不能编。
   1.10.0 的进展：修掉"只按配置文件在不在判装没装"，Gemini CLI 由假「未安装」变成真认证；
   顺带修掉"装前无配置文件时还原会留一个空文件"。

② 两个用户、两个不同 Agent 完成串门        —— ✅ 通过
   证据：docs/evidence/visit-2user-1.10.0.txt（39 项）
   两个独立进程、两个 DSH_HOME、两份独立 Ed25519 身份；
   邀请→验签→回名片→（加密）求助便签→解密→真落任务；改一个字符/过期都验不过。

③ 三个 Agent 完成会议并生成任务            —— ✅ 通过
   证据：docs/evidence/meeting-3agent-1.10.0.txt（41 项）
   claude/codex/dsh 三进程 → 意见 → 分歧 → 投票 2:1 → 逐项了结议程 → 结会 → 真出 2 条任务。
   反例也验了：议程没结论时结会被拦住，且一条任务都不落。
   ⚠️ 边界：三个 Agent 的"意见"是脚本写死的，不是三个大模型真在辩论（要接 API key）。

④ 记忆授权 / 导出 / 删除即时生效            —— ✅ 通过
   证据：docs/evidence/twin-1.6.2.md + gate-1.10.0.txt
   可见性闸门（private/friend/room/public）、export（json/md）、forget（按 id/查询/all）；
   1.10.0 新增 作用域（personal/project/team/global）+ 有效期（TTL 到点不再召回、写盘时清）。
   红队验过：public 视角召回不到 private；拿别人的 id / 带路径穿越的 id 删不掉东西。

⑤ 外部动作审批、日志和紧急停止可验证        —— ✅ 通过
   证据：docs/evidence/security-redteam-1.10.0.txt + gate-1.10.0.txt
   审批：deck_policy 的 confirm 规则 + strict 模式（不带 confirm:true 不执行）；
   日志：每次工具调用都落一笔审计，deck_audit 能 tail/query/export；
   紧急停止：deck_automation stop 落盘，跨进程有效（另一个进程 stop，正在跑的宿主下一拍就不动）。
   1.10.0 起策略**真的接线**（deny 的工具不执行），由 tests/policy-wiring.test.mjs 从宿主工具带真调证明。

⑥ 生产环境支付 + Webhook + 退款闭环        —— ❌ 未通过（本机没有商户号）
   证据：docs/evidence/pay-1.10.0.txt（37 项）+ docs/evidence/reconcile-1.10.0.txt（15 项）
   ✅ 链路本身真跑通：真 HTTP POST → 渠道回执 paid:true 才发放 → 落盘 payment.ref →
      幂等（重复确认不重复扣款）→ 退款 → 账本冲正 → 皮肤重新需要授权。
   ✅ Webhook 回调：1.10.0 加进自动化（真起 HTTP 服务器收回执，发不出去不算任务失败）；
      渠道侧 webhook 幂等与验签在 lib/billing/idempotency.js 与 sign.js。
   ✅ **对账**（1.10.0 新增，见 reconcile-1.10.0.txt）：拿渠道对账单跟本机订单逐笔勾对，六类差异
      （漏单/未真扣款/金额不符/状态不符/流水号不符/渠道重复）逐条报出来，**只报不改账**。
      不需要商户号就能验，已验 15 条；deck_market action=reconcile 真机跑过四种场景。
   ✅ **发票数据**（1.10.0 新增，见 invoice-1.10.0.txt）：已付订单能开出编号稳定、
      字段齐全（抬头/税号/金额拆分/税额/行项目/渠道流水号）的发票记录，可查可导出。
      13 条单测；deck_market action=invoice 真机跑过开票/重复开/列表。
      **明说不是税务合规的电子发票**；税率不配就写「未配置」，绝不编一个 6% 冒充已含税。
   ❌ **真实商户号没有**：AGENTDECK_PAY_PROVIDER/AGENTDECK_PAY_URL 未配时一律回
      「环境未配」，订单停在 created，不写 payment、不编流水号。
   ❌ **税费**：只有「按税率拆分票面金额」这一层算术；**申报 / 缴纳 / 抵扣没做**，
      也不该由客户端插件做。
   ❌ 主动「去渠道拉流水」：没验过（拉流水要商户号）。
   **所以对外不许说「真实支付」**——只能说「链路通、只差一个商户号」。

⑦ 断网、崩溃、升级、迁移可恢复              —— ✅ 通过
   证据：docs/evidence/recovery-1.10.0.txt（27 项）
   断网时 Hub 照常起、核心操作真落盘；SIGKILL 撕状态再猛写 8 轮撕裂 0 次；
   低 version + 老字段读得回写不丢；整棵状态树搬家后同一 teamId 读回同一块板。

⑧ 提示词注入与跨用户访问测试通过            —— ✅ 通过
   证据：docs/evidence/security-redteam-1.10.0.txt（11 项）
   注入：记忆投毒（载荷原样存、副作用为零）、便签标题塞命令（只变成任务标题）；
   越权：无令牌/假令牌/过期 401；A 队令牌读不到 B 队（403 且不回显）；冒名领活/交活/发言 403；
   串门 scope 越界、改一个字符签名即失效。
   **真修掉两个洞**：跨团队越权读（query.teamId 覆盖令牌团队）、冒名（body.memberId 覆盖令牌身份）。

⑨ 零跨用户数据泄漏事故                      —— ✅ 本机范围内通过（有限度）
   证据：同上 + docs/evidence/e2ee-1.10.0.txt
   1.10.0 补上**私密串门端到端加密**：X25519 协商 + HKDF-SHA256 + AES-256-GCM，
   AAD 绑便签 id/类型/双方公钥；加密后便签无 payload 字段，明文不上线；
   解不开时明确拒收（no_box_key / cannot_decrypt），绝不静默退化成明文。
   ⚠️ 边界：这是匿名密钥交换，**不防中间人**（无 CA、无带外指纹比对）；
      邀请函本身要当秘密对待。
   ⚠️ "事故"这个概念需要真实多用户长期运行才有意义；本机证据只能证明
      "已知的越权路径都被堵住且都有回归测试"，不等于"生产环境零事故"。
